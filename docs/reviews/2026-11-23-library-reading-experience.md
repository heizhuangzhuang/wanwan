# 资料模块深度阅读体验评审

日期：2026-11-23。应用基线：`dbf777e`。本轮交付体验结论与证据，应用功能未在本轮修改。

## 结论

当前已具备可用的纵向阅读流、目录、搜索和长文入口，但还不能按“适合孕妇沉浸阅读的成熟产品”验收。主要障碍是公开内容混入测试材料、文章缺少有效介绍、正文格式错误、读后找回能力不足，以及网络中断导致内容清空。

专家走查暂评约5/10，仅用于排定修复优先级，不代表真人访谈、用户满意度或统计结论。

本轮从用户研究、认知走查、界面审查、交互文案、可访问性、探索式测试、小程序调试与代码验证八个角度检查。场景假设是一位刚从胎儿超声获知疑似足内翻的家长，希望理解情况、查产前检查资料、阅读可信解释，并留到下次继续看。

## 验证条件与边界

- 微信开发者工具模拟器，显示机型iPhone 12/13 Pro，390×844，基础库3.18.0；不等同于真机iOS测试。
- 使用当前开发工具连接的真实API数据，运行时开启`wx.cloud.callContainer`。没有向后台新增、修改或删除文章。
- 故障恢复通过独立的临时测试进程编译当前小程序代码、模拟请求失败复现；没有断开生产网络或修改生产服务。
- 本轮未实际向微信联系人发消息，未做公众号投放、正式版上传、真机屏幕阅读器或大字号验收。
- 当前首批3篇文章没有可用封面地址，没有足够的真实图文内容完成整条图片阅读链路验收。不能用上一轮的临时布局配图代替这项验收。

## 优先问题

### R1 · P1 · 断网返回会清空已经读到的内容

**复现：** 正常加载资料流或长文，将后续请求模拟为网络失败，再执行进入前台时的重查逻辑。

- 资料流：加载前1条，失败重查后0条，`featuredError=true`。
- 长文：加载前存在正文节点，失败重查后正文节点0个，出现“暂时无法加载，请重试”。

**用户影响：** 切换应用、网络抖动后无法继续阅读，也可能丢失当时的阅读位置。把“已经收到内容”与“尚未加载成功”处理成同一种失败状态。

**建议：** 普通网络失败保留当前内容，显示“暂未同步，可继续阅读”；已确认404、撤回或权限变化时清除对应内容。首次加载失败与返回重查失败分别处理。分享与重新访问仍需核对当前公开状态。

**相关实现：** `miniprogram/pages/library/library.ts`的`loadFeatured`在失败时将流数据替换为空数组；`miniprogram/pages/reading/reading.ts`的异常分支对网络错误和内容不可访问均清空正文。

### R2 · P1 · 公开流混有测试材料，无法建立可靠的阅读预期

实际看到测试文章、安装欢迎页以及标明虚构的联调资料；用户不容易判断哪些内容正式可用。这里不应仅靠客户端隐藏标题中含“测试”的文章。

**建议：** 在Halo明确正式内容发布范围，测试材料保留在测试环境或取消公开。建立上线核对项：主题相关、来源完整、摘要完整、内容已经复核。展示名使用真实公开的整理者身份，不虚构医生认证。

**证据：** [资料流首屏](assets/2026-11-23-reading-audit/feed-real-content.jpg)。

### R3 · P1 · 摘要与长文开头都没有优先回答读者的问题

多篇卡片的介绍只有“打开导读，查看内容与资料出处”。它能避免错误摘录引用头部，却不能帮助用户决定是否值得读。首篇长文开头的623字符主要用于英文出处、作者、机构与分析缘由，关键内容在后面。

**建议：** 由整理者核对后补2至3句介绍，说明这篇能了解什么、适合哪一阶段。长文开头放简短的“这篇会讲什么”，保留来源并折叠详细题录。不能通过猜测或自动编造医学摘要填空。

**证据：** [长文第一屏](assets/2026-11-23-reading-audit/article-first-screen.jpg)。

### R4 · P1 · 表格和强调标记直接暴露在正文里

“核心分析维度速查表”显示为多段竖线文本；部分段落显示原始`**`。这不是字体颜色的问题，而是内容格式与HTML阅读器的输入不一致。

**建议：** 先核对Halo发布内容的格式。编辑器发布时规范为HTML表格和强调；需要兼容Markdown时，使用受控的解析与清洗流程。手机上的宽表应转成逐项信息行或可明确横向滚动的表格，保留可读标题。

**证据：** [表格画面](assets/2026-11-23-reading-audit/raw-markdown-table.jpg)、[强调标记](assets/2026-11-23-reading-audit/prenatal-section.jpg)。

### R5 · P1 · 长文缺少收藏、最近阅读和阅读进度

阅读页底部只有目录、资料库和分享。当前收藏与最近阅读的数据结构只处理资料卡；读完这篇12分钟的长文，不能从“我的”快速找回，重新打开也没有回到上次章节的入口。

**建议：** 用带类型的标识支持文章与资料卡收藏、最近阅读；记录文章的最后章节与更新时间，重新打开提供“继续上次阅读”。文章撤回后清除或明确显示失效状态。公开文章阅读标记仅需轻量本机存储，不需要附带孩子的健康资料。

**证据：** [我的](assets/2026-11-23-reading-audit/my-reading-history.jpg)。相关文件：`reading/reading.ts`、`reading-shelf.ts`、`shelf/shelf.ts`。

### R6 · P2 · 文章仍保留面向专业读者或分析任务的表达

实际内容有“核心分析维度”“方便您直接引用分析”等表述，也有“100%正常”等绝对化用语。对刚获知疑似情况的家长，这些内容既增加理解负担，也容易形成过强预期。

**建议：** 按“读者现在的问题→说明→适用条件→可以带去问医生的问题”重新编辑。医学判断由专业人员复核，本轮不把措辞问题当作已经完成医学事实审查。

来源核对：所引Cady等人的原始报告确实存在，原文定位为医疗从业者的临床报告，不能直接等同于家长说明书。[PubMed原始记录](https://pubmed.ncbi.nlm.nih.gov/35104362/)、[PMC原文](https://pmc.ncbi.nlm.nih.gov/articles/PMC9645716/)。

### R7 · P2 · 部分阅读控件仍偏小

实际测量：顶部“折叠章节”约58×23.2px，横向章节按钮约325.2×31px。它们低于本项目44px点击高度的目标；而底部目录、阅读全文等较大的入口更容易操作。

**建议：** 增加真实点击区域，而不只是放大文字；保持上方搜索、阶段筛选与产前专项的既定布局。目录中已有序号的标题还会出现“1. 1.”，应在显示层统一编号。

**证据：** [目录列表](assets/2026-11-23-reading-audit/article-toc.jpg)。

### R8 · P2 · 阅读页把“分享”放在最强操作位

用户主要任务是阅读和稍后继续，底部最大的绿色按钮却是分享，收藏与进度尚不存在。

**建议：** 在补齐收藏与继续阅读后重新安排操作优先级。分享保留为次要入口，目录始终可找到，不以悬浮按钮遮盖正文。

## 配图与可访问性结论

- 文章封面、正文图片处理代码已存在，但本轮真实数据没有完成图文预览、放大、关闭、返回与弱网加载的完整链路。需要用一篇可公开展示的实际图文文章做验收，分别核对后端字段、CMS配置及图片地址可用性。
- 正文`#475145`/`#FFFDF9`对比度约8.17:1；辅助信息`#61685E`约5.66:1；绿色链接`#376052`约6.99:1。已测色组的文字对比度通过通常正文要求。
- 这不等于整体通过可访问性验收。VoiceOver、系统大字号、Android与真实设备触摸仍未覆盖。

## 修复顺序与验收条件

1. 优先修复R1：首次失败、返回时失败、404和撤回分别回归；普通断网不清空已有正文。
2. 同步整理R2、R3、R4：准备至少一篇正式图文文章，补合适的摘要，规范表格与强调，移除公开流中的测试材料。
3. 补齐R5：文章收藏、最近阅读、继续上次章节，检查撤回与换文章后的状态隔离。
4. 再处理R6至R8：面向家长的表达、触摸区域、目录编号和操作优先级。

原有小程序61项测试本轮重新执行，全部通过；R1的复现实验揭示现有测试未覆盖返回前台时的失败保留。新增用例应围绕真实用户中断、恢复、找回和图文阅读，而非只断言页面字段或按钮存在。
