# 投资人、CTO与孕妇使用情境审查

2026年11月12日 · 对应[修订计划书](../business-plan/business-plan.md)与[技术实施方案](../architecture/technical-plan.md)

本次是基于既有计划书、一个家庭的需求素材和官方技术资料开展的桌面审查。投资人和CTO是评审立场，孕妇视角是具体情境推演；没有新增真人访谈、临床专家评审、签约机构或产品测试结果。下文不将模拟情境当作用户证言。

## 1 投资判断：有明确痛点，但融资论据尚未闭合

这个项目值得验证的地方，是跨阶段资料与问题持续丢失：超声发现后不知道怎样复核，羊穿后不知道还有哪些报告未返回，产前咨询与出生后治疗又重新开始讲述。若能让一个家庭带着清楚的问题和完整资料完成下一次就诊，就有可观察的价值。

目前不支持仅凭现有计划书就投入完整平台开发。原因不是功能不足，而是尚未证明：需求在多个家庭重复出现、有人愿意持续承担专业审核、机构或家庭会为具体服务付费。单病种规模也限制了仅靠家庭订阅形成大型业务的可能性；机构业务是待验证的第二条收入路径，不能直接当成已经成立的扩张依据。

### 投资人会追问的五件事

| 问题 | 目前能回答什么 | 下一轮需要的证据 |
| --- | --- | --- |
| 为什么用户不用微信收藏、文件夹和家长群？ | 方案推测资料与问题之间缺少衔接 | 用户带着自己的真实任务比较两种方式，观察遗漏、用时和完成情况 |
| 最先服务哪类家庭？ | 全阶段需求清单较完整 | 首期主招募“首次提示至一次专业咨询后的回填”；出生后家庭另做小规模连续性验证 |
| 谁愿意付钱，为何付？ | 家庭工具及机构宣教随访均为假设 | 具体服务试用、实际付费或明确拒绝理由；机构端找到业务负责人和采购路径 |
| 服务是否需要大量人工？ | 现有计划承认专业承接重要 | 每个家庭实际处理耗时、需要哪类人、返工和不能处理的问题占比 |
| 有什么难以替代的积累？ | 场景、内容和流程可形成基础 | 医生实际采用的摘要、可持续审核、带随访的授权经验、机构持续使用记录 |

不把病历数量、AI回答次数、用户焦虑带来的浏览和未来多病种市场作为当前竞争壁垒。计划书中的市场估算只能作数量级讨论，必须与实际可触达家庭、可服务家庭、付费家庭分开。

### 商业模式的修订意见

第一阶段基础知识、手动问题单、基础资料导出和就医入口保持可用，用来验证是否帮助完成任务。家庭端只试验边界明确的资料整理或行政协助，记录交付和退款条件；不能先假设孕妇愿意长期订阅，也不能通过锁住个人资料逼迫续费。

机构端从一个科室的具体问题开始，例如初诊资料不齐或宣教重复，不一开始卖覆盖整个医院的系统。试点必须区分“医生觉得有用”“科室愿意改变工作流程”和“机构能够采购”三个层次。正式医疗服务仍由有条件的机构承接，平台不以检测或转诊数量获取激励。

## 2 CTO判断：业务事实和授权比AI更难

现有计划提出了很多正确原则，但不足以直接交给研发。需要补齐的是：一个家庭和一个胎儿怎么建模，一次羊穿与多项检测怎样分开，转述与正式医嘱怎样显示，家属撤权后文件链接怎么办，提醒失败时任务是否仍在，以及谁处理永远停在“等待”的申请。

技术方案已将这些问题拆为数据实体、状态流转、接口、服务端权限与验收项。默认选择模块化单体，成熟云数据库和文件存储承担基础能力；首版不建设复杂医疗数据平台，也不要求AI才能完成资料整理。

| 原方案容易被误读的地方 | 修订决策 | 为什么 |
| --- | --- | --- |
| 全流程等于第一版全部功能 | 43个场景是需求覆盖库；首版只实现共同底座及主要闭环 | 减少研发范围，同时保留跳步、暂停及不同结局 |
| 论坛和小程序只是两个界面 | 共用身份与公开内容接口，私密病例独立授权 | 避免社区登录自动扩大资料访问范围 |
| 家属协作等于家庭全部共享 | 资源和动作级授权，可撤回 | 伴侣并非天然拥有全部遗传资料权限 |
| 用AI读报告可直接给下一步 | 先手动；提取只能形成待核对草稿 | 报告内容、临床判断、计划执行是不同层次 |
| 通知发出就完成服务 | 站内待办为原始记录，通知失败可见 | 微信授权、模板和调用可能失败 |
| 有备份就能恢复资料 | 数据库、对象文件、授权和删除清单联合恢复 | 数据库恢复不必然恢复报告文件 |
| 提供医生卡片等于能找医生解决 | 收录、合作、受理、完成分别标记 | 软件不能替代真实服务供给 |

具体厂商比较、官方依据及测试方法见[技术实施方案](../architecture/technical-plan.md)。选型是当前建议，尚未进行小样验证，不能据此宣称已具备上线能力。

## 3 孕妇视角：六条情境走查

以下人物均为虚构，使用真实可能发生的任务约束；不是受访者原话或临床案例。走查关注她当下要完成什么，以及产品是否增加负担。

### 情境一：刚拿到超声报告，不愿填写档案

她在医院走廊用手机搜索，最想确认接下来找谁、带什么、这份描述是否已经确定。此时显示全生命周期、论坛热门帖或长篇问卷，都会增加负担。

修订后从“刚收到超声提示”进入，先看到短说明与可修改的问题单。孕周和城市可后补，上传报告为可选。首个有效动作是带走一份复核问题，不是完善资料。她应知道哪些尚待专业复核，而不是被页面上的疾病名引向结论。

**测试任务**：不登录、不上传，在页面中找到复核该问的两个问题，并解释哪些事项目前未知。若她误以为系统已经确诊，判定页面失败。

### 情境二：已经取样，一份报告先出，另一份仍在等

她收到一份结果正常的报告，想知道是否可以停止等待。原方案虽然介绍分项管理，但如果页面只有一个“羊穿已完成”，仍会误导。

修订后将取样与实际检测分开，每项显示报告是否收到、是否解释、预计时间来自哪里；不知道项目名称时允许保存受理单并标记待核实。平台不自行补齐“标准套餐”。看到一份正常报告后，其他项目状态不变。

**测试任务**：给出三个项目的合成受理单和一份结果，让她判断还有什么未完成、该向谁核实。准确理解比点击速度更重要。

### 情境三：结果未明，伴侣想让她把报告发到群里

她希望伴侣帮助预约，但不想公开全部遗传信息。若邀请家属即默认开放所有资料，产品会迫使她在获得帮助和保留隐私之间做选择。

修订后可只授权预约任务和选定报告；公开经验从私密档案另生成草稿。发帖前展示具体公开内容，默认不带报告图；“匿名昵称”不能被宣传为无法识别。撤销权限会停止后续访问，但不假装能收回对方已经下载的文件。

**测试任务**：给家属一个任务，保留一份报告不可见，再撤回授权。若她不知道对方能看什么，或误认分享撤回能删除对方手机上的副本，判定授权说明失败。

### 情境四：人在外地，看到医生介绍但没挂上号

她需要安排车票和请假。一个“已提交会诊”页面如果没有机构受理人和时间，比单纯的官方入口更容易让她误以为已经安排妥当。

修订后没有正式接入的机构只显示已核实导航、材料清单和用户自己保存的预约情况。真实合作服务必须显示谁接收、是否补件、何时排期；被拒收或长时间未处理时，给出实际可用渠道。小程序可以整理不同科室的问题，但不能假装已组织MDT。

**测试任务**：用无号源、机构拒收、材料缺失三个情境测试，要求用户说清下一步由谁做。若她认为平台已替她预约成功，判定信息失败。

### 情境五：孩子开始治疗，医院调整了复诊和支具安排

照护者换成祖辈，旧提醒仍在，父母不确定该按哪次记录执行。如果系统只不断添加任务，长期使用会变成新的混乱来源。

修订后每条安排关联来源及版本；录入新方案时对照旧任务，由用户确认取消或替代。记录佩戴困难用于向医疗团队反馈，不自动调整时长，也不对漏记家庭打“依从差”标签。只有主要照护者主动参与后才开放必要记录。

**测试任务**：修改一个复诊日期并替代旧计划，检查旧通知、家属视图和导出摘要一致。记录不完整应显示未知，不能默认没执行医嘱。

### 情境六：她不想再收到孕期提醒

原因可能是情绪负担、换了平台、妊娠结局变化，或只是暂时不需要。要求先说明结局才能关闭提醒，会造成二次负担。

修订后随时暂停阶段提醒与社区推荐，不强迫填写原因。资料保留、导出、删除分开选择；重新进入时由用户选择阶段，不自动跳到出生后。非预期结局的支持内容按用户主动选择出现。

**测试任务**：关闭提醒、保留资料、之后重新进入。系统不能自动重新订阅或显示庆生、育儿推广。

## 4 必须先改、试点再验和后续再做

| 优先级 | 事项 | 完成标准 |
| --- | --- | --- |
| P0 文档与原型 | 明确首版交付和哪些事情靠真人 | 每项功能有用户任务、责任人和完成条件 |
| P0 首版研发 | 归属、版本、授权、撤回、删除、异常状态 | 越权、错配及核心失败路径测试通过 |
| P0 服务准备 | 内容审核者、社区处理时段、医生信息核实 | 有真实承接人员及记录，不是虚拟专家头像 |
| P1 真实试点 | 摘要是否有用、用户是否能完成下一步 | 用户实际使用，专业方能快速理解，反例被记录 |
| P1 商业验证 | 家庭服务交付、机构工作流和付费 | 有行为或付款证据，不能只问“愿不愿意” |
| P2 增强能力 | OCR、AI摘要、正式机构接口、成熟论坛 | 每项独立证明质量及维护可行性后进入 |

本次已完成文档层面的P0修订；研发、真实审核和用户测试尚未完成。表中的优先级不表示已有这些岗位或人员。

## 5 下一轮怎样获取真实证据

维持原计划约24至30个家庭的分层研究，但先做6至8人的小批次任务测试，尽早修正页面再继续招募。覆盖首次发现、检查等待、结果未明、未选择某项检查、出生后治疗、长期随访及暂停情境。样本用于发现问题，不外推全国支付率。

访谈先问过去一次真实事件与使用过的工具，再让用户在合成材料或其自愿提供的最小资料上完成任务。避免先讲产品理念后问是否喜欢。记录是否独立完成、误解在哪里、需多少解释、是否真正用于就诊，以及不愿使用的原因。高负担情境允许退出和不回答。

专业方先找产前诊断或遗传、小儿骨科和门诊护理等不同角色评估摘要和任务流；采购判断另找有职责的机构人员。要求指出“不愿看”“会误导”“增加工作量”的地方，不能只收集赞同意见。未经同意不在对外材料展示身份或合作。

### 指标口径与停止条件

“有用准备任务完成率”的分母为观察期内确有就诊或治疗节点、同意参与且尝试工具的家庭；分子为实际带走并使用问题单、摘要或确认安排的家庭。研究需同时报告样本量、观察时间、失访和退出，不用活跃用户替代所有入组家庭。

“关键任务无协助完成率80%”保留为初始讨论阈值，须附任务定义和测试人数；小样本达标不能证明市场成立。专业人员可用性记录是否能找到关键信息、是否误解来源、是否愿在真实流程使用，不以“觉得好看”计为通过。

若连续测试发现用户依旧只需要一次性文章，先收缩到知识和导航；若资料工具有用但机构暂不采购，继续验证家庭价值，不把医院合作写成必然；若必须依靠无法持续提供的人工咨询才能产生价值，则先解决供给再扩张。越权、资料错配或严重医学误导应暂停相关功能，完成修复与复测后再继续。

## 6 本次修改落点

计划书的投资概要、产品结构、商业模式、分期验收、技术责任和用户验证已经同步修改；保留原有四张流程图、14步行动清单、43个复杂场景及专业分工。新增第39节技术落地摘要，并将深入选型、数据模型和验收放入独立技术文件，便于投资人阅读主线，也让研发能审查细节。

现阶段最值得展示给投资人的演示，是一个真实用户任务从困惑到就诊准备、再到回填安排完整走通。完整功能列表和AI演示可辅助说明，但不能替代这条证据。
