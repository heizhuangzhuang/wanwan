# 小脚丫家庭记录双端开发设计

2026-11-25 · 面向 Halo 插件、Nuxt Web、微信小程序和测试人员。本文记录设计与第一阶段实现。产品边界见[双端登录需求](./家庭记录双端登录需求.md)，可复现的验收步骤见[测试设计](./家庭记录双端测试设计.md)。

## 3. 身份、授权和扫码

1. 小程序在用户触发私人操作后换取微信临时凭证。服务端核验后用固定 AppID 与微信身份的唯一绑定，查到或创建同一个 Halo 普通用户。账号绑定有唯一约束及创建中状态；创建 Halo 用户与保存绑定分步失败时按同一预约编号重查、续办。不得按昵称认领旧数据。
2. Web 建立短时挑战，把浏览器秘密放进安全 Cookie，返回只含公开挑战引用的小程序码及同手机可用的配对码。手机先登录，在确认页展示网站、设备和两端一致的核对数字，再主动确认。挑战按「待确认 → 已确认 → 已兑换」转换，待确认也可取消、过期。服务端原子消费，一次挑战只能生成一份浏览器会话。兑换成功但响应丢失，可用新的挑战重新登录。
3. 浏览器使用同源 HTTPS、Secure/HttpOnly/SameSite Cookie；变更请求校验来源和防跨站令牌。小程序持有独立可撤销会话。会话、配对状态和限流跨实例共享。渠道由服务端入口判定。私有读写逐次验证会话、Halo 用户状态、档案归属和对应工具授权。停用、删除、登出必须能失效，不能仅依赖清除本机缓存。
4. 登录、两类工具的监护人云存储授权、微信订阅是三种独立决定。仅登录时不上传本机旧记录。授权需记范围、版本及确认时间，换版按实际范围重新确认。撤回或清除提升档案世代编号，旧离线操作不能在再次同意后复活。
5. 待返回目标只保存站内允许的页面与操作；登录完成后重新核对目标记录和当前计时。扫码取消或过期返回原页。退出或换号立即遮挡私有视图、清除会话和内存，旧账号队列只在本人重新验证后恢复，共用电脑支持主动清除本机副本。

## 4. 持久化与接口约定

建议新业务使用现有 MySQL 中由插件维护的表，Halo 用户主档仍通过 Halo API 管理。上线前在同版 Halo 与 MySQL 验证插件取连接、受控表迁移、事务、备份还原和多实例锁。项目目前用 ExtensionClient 保存旧私有扩展，不能假设跨多个扩展的调用天然构成一个事务。原型验证失败时暂停新版写入、保留旧工具，重新评审存储实现。

| 逻辑对象 | 必需约束和用途 |
| --- | --- |
| 身份绑定、会话、登录挑战 | 微信身份唯一、Halo 用户引用稳定且不复用；会话密钥只存摘要，带渠道、有效期和撤销标记；浏览器绑定和兑换用一次性条件更新。 |
| 档案、授权、档案版本 | 首版每名家长一份；石膏、支具授权分别记录。每个档案有迁移状态、世代编号、统计时区和修改序号。 |
| 石膏条目、佩戴时段、当前计时 | 业务键含档案编号，条目有版本；每份档案最多一行当前计时。开始、停止以该档案行锁或等效数据库原子条件串行化。 |
| 操作回执、删除标记、提醒任务、导入批次 | 回执唯一键为档案＋世代＋操作编号；记录请求摘要及原结果。删除标记使离线编辑可检测冲突。复诊提醒保存任务版本，导入批次记录来源摘要、进度和逐项结果。 |

家长填写的注意事项、复诊问题和支具观察等敏感字段用应用侧认证加密保存；回执若需暂存同类内容，也要受相同保护。密钥按用途与版本管理，备份包括对应版本的受控恢复途径。删除时清理在线正文和临时导出，删除标记仅保留拒绝旧写所需的信息。恢复历史备份先应用删除、停用及撤回清单，再开放读取。回执保留窗口需覆盖客户端可自动补传的窗口；超过窗口的草稿必须先重新读取云端并由家长核对，避免清理回执后将旧操作当作新增。

新接口为拟议逻辑契约。Web 统一走站点下的同源代理，小程序经云托管调用同一插件。私有路由和响应均禁用共享缓存；严禁把会话、配对码、微信标识和家庭记录放入访问日志、统计事件或公开 API。

| 操作 | 输入及约束 | 成功与失败约定 |
| --- | --- | --- |
| 创建、确认、兑换网页挑战；小程序登录；退出 | 确认须有小程序会话，兑换须持有发起浏览器的秘密。配对请求限制尝试次数和频率。 | 超时或取消后无法兑换；重发开始新挑战。日常私人 API 返回 JSON，过期返回 401，浏览器不应收到 Halo 登录页 HTML。 |
| 读取档案、授权、导出、删除 | 从会话取家长身份。仅可访问本档案。未授权只回授权状态；提供独立的撤回、删除和导出操作。 | 无权访问第三方条目统一返回 404；缺少本档案所需授权返回 403。 |
| 新建、改动、删除石膏或佩戴条目；开始、结束计时 | 命令携带 operationId、档案世代、条目编号和已读版本。新条目编号在第一次落本机前确定。结束必须携带 timerId。 | 校验当前权限后查回执，相同内容重试返回原结果；复用同一编号但内容不同返回 409。版本过期返回 409 并允许核对、另行提交。无效字段返回 422，超限返回 413 或业务限额错误。 |
| 读取更新、迁移预览与提交 | 首版可使用分页快照加档案版本；读到版本变化须重读。导入提交带批次编号、预览版本和逐项决定。 | 只有服务端已持久提交才返回成功。服务暂不可用回 503；客户端保留队列，按退避策略重试。 |

例如，手机开始佩戴产生操作 A 和计时 T；网页停止产生操作 B，引用 T 和已读版本。服务端在同一事务内校验 T、落一条已结束时段、清除当前计时、更新版本并写 B 的回执。网页超时再发 B，返回同一时段。旧手机用另一个操作再结束 T，应显示它已结束；即便家长又开始了下一段，也绝不能结束新的计时。

### 接口交接样例

拟定插件前缀为 /apis/family.xiaojiaoya.run/v1alpha1，Web 同源入口为 /xiaojiaoya/api/family。路由名在首轮契约测试中冻结。POST /auth/mini、POST /pairings 和浏览器兑换入口开放必要的未登录访问；配对确认须有有效小程序会话。GET /me、POST /consents、GET /cast/entries、GET /brace/state、POST /commands、POST /imports/preview 和 POST /imports/commit 走家庭身份验证。客户端只可提交业务输入。插件从已验证会话解析 Halo 主体，忽略客户端自报的账号或渠道。若桥接会话不能进入 Halo 权限链，此项须在原型阶段解决后才能开放读写。

按建议，线上起止采用服务端认可的操作时间，离线起止保留首次点击且成功落本机的时间。统一存绝对时间和档案时区，首版统计使用 Asia/Shanghai；结束早于或等于开始、设备时间倒拨、两个时段重叠时保留待核对输入，禁止自行改时间。先验证当前共享账本在不同时区的分日一致性。

| 请求样例（简写） | 服务端结果 | 客户端动作 |
| --- | --- | --- |
| POST /commands，type=brace.stop，operationId=B，timerId=T，expectedVersion=7，generation=2，occurredAt 为带时区时间戳 | 成功返回 operationId、timerId、最终时段 ID、version 和服务端确认时间；同一条 B 重试取得相同回执 | 本地以事务保存回执并移除该条待传命令，然后刷新统计 |
| 同一 T 已结束或版本已变化 | 409，业务码 TIMER_ALREADY_CLOSED 或 VERSION_CONFLICT，给出当前可见版本与条目 | 展示当前结果，保留本机候选供核对。仅对可访问记录显示内容 |
| 401 / 403 CONSENT_REQUIRED / 409 GENERATION_CHANGED | 分别表示需要同一人重新登录、确认授权、旧队列来自已撤回或清除的档案 | 暂停队列；归属或世代改变时禁止自动重放 |
| 502、503、超时、断线、429 | 外部登录失败或服务不可用、结果暂不明确、请求频率过高 | 展示待确认状态；已有业务操作使用原编号重试。临时微信登录凭证按需重新获取 |

## 5. 弱网、旧数据和提醒

**设备待传。** 将操作、原值、归属、世代和客户端顺序在同一次本机提交中持久化，再更新界面。支持同一台手机离线开始后离线结束，开始成功时分配稳定的 timerId，结束引用它。按档案顺序补传；某条冲突时暂停它及依赖它的后续操作，保留本机候选和云端现值。关闭页面或应用不得销毁已落盘队列。退出前显示待传条数；本机空间不足时保留可复制的输入，明确提示保存失败。未登录或已明确失效的设备不能创建新的私有记录。服务端仅在验证当前归属、授权和世代后接受补传。

**迁移与回退。**

1. 用已验证的微信身份关联原石膏和支具云档。两者旧资源名计算有不同前缀，[旧加密实现](../plugin-wanwan/src/main/java/run/wanwan/notice/CastJournalCipher.java)把资源名参与密文认证。历史解密密钥只帮助解密，旧索引密钥或原资源名映射才能帮助定位。未知密钥、查到多份或原档应存在却无法核对时，报告待恢复，禁止创建空档覆盖。
2. 本机导入先只读预览，列出归属、日期范围、条数、进行中计时和冲突。含时段、目标计划、确认未穿日期、随访、观察、问题清单和旧版目标；将旧版只有目标分钟数的记录按固定迁移基准日转换，保证重跑一致。按原条目 ID 或稳定来源键去重，保留有歧义的重叠段给家长核对。导入分批到暂存区，最终确认才可见；重复确认同一批次返回同一结果。
3. 同源升级可只读发现旧 IndexedDB。原 Web 如果通过 HTTP IP 访问，迁至 HTTPS 域名后浏览器隔离了旧存储。保留在旧来源本地导出 JSON 的路径，文件由家长在新站预览确认导入；旧 HTTP 页面不承担新账号登录。小程序保留原存储键和双槽读路径。首次登录不得把旧记录自动分配给当前家长。
4. 本地 JSON 上限按旧客户端实现核实，常量为 24 MiB；旧云归档限 2 Mi 字符、HTTP 正文限 4 MiB，字符和字节分别测量。本地能打开但不能整体上传的文件应分批导入，无法导入时提供可用备份与失败原因，禁止截断。
5. 灰度按档案走「旧库可写 → 冻结旧写并排空在途操作 → 比对并迁移 → 新库可写」。旧版保存、清空、整档替换、提醒调度都有同一写入栅栏；冻结和比对之间若旧版本已变，重新读取。迁移前仅迁移器可写隔离暂存，其他流量只读。分别核对字段、数量、进行中计时和授权。老版本收到可识别的更新提示，并保留本机导出路径。回退先关闭新版写入、导出并保留新增操作和回执；未验证回放与双向一致前只读服务，禁止将迁移前的整库备份直接覆盖线上库。

**微信提醒。** 延续每份石膏档案最多一项待发。改期或删除在保存记录的同一事务内使旧任务失效；改期后显示「重新订阅提醒」，由家长在小程序确认并满足有效订阅和时间窗后创建新任务，Web 可显示状态。调度任务领取时核对条目版本，回写时核对任务 ID。已发消息无法撤回；发送前登记发送中，微信结果未知显示「发送结果待确认」，不得盲目重发。迁移灰度期每份档案只能有一个调度方。测试环境拦截真实微信发送。

| D5 灰度与验收 | 在试点档案开放新写；观察冲突、失败、未确认提醒、队列积压和迁移差异的汇总数。 | T01–T16 与一次隔离恢复演练。无越权、已确认写入丢失、重复停表、旧数据误覆盖后再逐步放量。 |

测试先提交失败样例和预期响应，开发再提交实现；涉及权限、并发或恢复的改动由另一角色复核。发布负责人记录每次切换的版本、备份点、密钥版本、试点档案数量、验证结果和回退状态。日志只用不包含身份和记录内容的追踪号。生产家庭写入要求确认实际使用持久 MySQL；当前[启动脚本](../deploy/cloudrun/entrypoint.sh)允许未配置 MySQL 的启动路径，不能以“容器健康”替代重启后的读回验证。




## 7. 本地联调与本次实现边界

- 在隔离的 Halo 实例中加载本分支的插件，沿用石膏服务的微信 AppID、AppSecret、隐私邮箱和加密配置，再设 `XIAOJIAOYA_FAMILY_ENABLED=true`。旧档样本应使用原加密索引密钥。数据库应为独立测试 MySQL。
- Web 本地用 `HOST=127.0.0.1 XIAOJIAOYA_FAMILY_LOCAL_HTTP=1 BACKEND_API_BASE=http://127.0.0.1:18091/apis/api.xiaojiaoya.run/v1alpha1 npm start`。先运行 `npm run build`，将后端端口替换为实际本地 Halo 端口。打开 `http://127.0.0.1:3000/xiaojiaoya/tools/family`，使用测试账号和测试记录。公网 HTTPS 的部署配置留待后续。小程序在测试环境确认网页显示的配对码。若体验版已包含 `pages/family/family`，可试 `XIAOJIAOYA_FAMILY_QR_ENV=trial`，扫码不可用时走手工输入。
- 第一次写入前可读取旧云端石膏与支具快照。第一次新版写入后服务端拒绝同档案的旧版写入，旧版数据可读。新旧逻辑共用 Halo 的 MySQL 扩展记录和版本比较更新。配对、会话、石膏和支具分别持久化。支具写入携带档案版本、操作编号和计时编号。
- 目前支具的自动补传覆盖计时开始和结束。待传操作按账号保存在本机，版本冲突后需要核对。石膏资料保存失败时会恢复已提交的本机草稿，由家长确认后重试。两端录入与编辑时段、Web 数据导出和两端撤回已接入。已有支具随访大屏仍提供本机档案和旧备份入口。新页可预览并合并旧 JSON，遇到有差异的旧数据提示冲突并保留原文件。
- 相比前文目标，目前回执仅保证最近一次支具操作的原请求重试，较旧请求通过版本拒绝重复执行。整档导入仍受旧云档大小限制。分批导入、个别冲突逐条合并、完整登录会话管理、跨实例 MySQL 压测、隔离备份恢复及微信真机验收是后续放行项。
