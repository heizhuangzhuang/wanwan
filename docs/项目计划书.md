# 弯弯开发计划

更新于 2026-11-18。实现盘点基于 `main` 提交 `ccc9829`。

弯弯是个人维护的足内翻知识导航。读者可以按阶段找到机构资料、论文题录、家庭经历和本站原创导读，再去原始来源阅读。运营者逐条核对并手动录入。首版交付 Web，公众号手动分发，小程序在主体和阅读入口验证后单独交付。

功能范围和验收用例见[产品需求与内容规范](./产品需求与内容规范.md)，实现方式见[技术架构与实施方案](./技术架构与实施方案.md)，收录和投诉处理依据见[个人运营与版权边界](./个人运营与版权边界.md)。

## 当前进度

- 已有 Halo 资料卡和专题后台、公开查询 API、资料卡关键词搜索、独立 Web SSR 页面、小程序页面骨架和部署模板。
- 本地已通过 Web 4 项测试、小程序 TypeScript 检查。按 `pnpm 9.15.9` 单独构建 Console 后，Halo 插件 JAR 打包成功，22 项测试通过。默认 Gradle 构建仍会拉取未锁定的 pnpm，本次在依赖安装阶段失败。
- 仓库没有首批真实内容的交付记录。Halo、MySQL、Web 全链路联调、生产部署、备份恢复和小程序真机与提审均待验收。

## 交付顺序

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 1. 可重复构建与 3 条资料试运行 | 修复默认构建，启动本地 Halo、MySQL、Web，在 Console 手动录入 3 条已核对的资料 | 标准构建能产出含 Console 的插件 JAR。真实服务走通草稿、发布、浏览、搜索、撤回；匿名读不到草稿和内部台账 |
| 2. Web 首版 | 完善编辑核对、Web 筛选与翻页、阶段导读、相关资料、反馈处理和首批内容 | 产品验收 P01–P04、P06–P09 的 Web 场景通过。首批以约 20–30 条核对资料为编辑目标，覆盖五个阶段，缺少资料时显示空状态 |
| 3. 上线准备与发布 | 生产部署、公开访问与管理入口隔离、真实联系方式、备份恢复、Web 发布条件确认、公众号手动发布 | 实际生产链路通过冒烟检查；P10 恢复演练通过；域名、HTTPS、备案和联系方式记录齐备；公众号首发按账号实际能力执行 |
| 4. 微信小程序 | 完成专题、导读、筛选分页、错误提示与来源入口，接入真实云环境 | 先记录主体、类目与所需跳转能力的核实结果，再投入正式接入和提审；完成 P05、P06、P09 真机验收，按实际平台审核结果发布 |

Web 先按自身发布条件推进。小程序能力核实可与 Web 开发并行。主体或类目不适用时，保留 Web 和公众号，是否调整主体由运营者决定。

## 上线后如何判断效果

用少量真实读者的反馈检查能否找到对应阶段的资料、识别来源类型并顺利到达原站。运营者记录核对每条资料的时间、失效链接、勘误和撤回情况。项目按个人免费资料站运营，运行成本以实际云资源、域名、备份和编辑时间核算。

公众 RAG、收藏同步、投稿、论坛、报告上传与个体诊疗服务均在首版范围之外。公众 RAG 如需推进，单独确认需求、语料权利和上线条件。
