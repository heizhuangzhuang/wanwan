# 弯弯：个人运营知识导航项目计划书

版本：5.0｜更新：2026-11-12｜状态：当前规划，未恢复代码开发。

配套：[产品需求与内容规范](./产品需求与内容规范.md)｜[技术架构与实施方案](./技术架构与实施方案.md)｜[个人运营与版权边界](./个人运营与版权边界.md)｜[文档目录与决策记录](./项目文档总目录与决策记录.md)。

## 1. 项目做什么

弯弯由个人以家长、资料整理者身份开发运营，面向产前发现胎儿疑似足内翻的孕妇及家庭，提供按阶段组织的知识导航。帮助读者从分散信息中找到可核对的原始来源，分清机构资料、研究论文和家庭经历，了解有哪些材料可以阅读。

首版采用 **手动精选录入＋原标题和来源＋独立撰写的简短介绍＋原文入口**。用户在本站选择材料，到来源网站阅读原文。平台自己的阶段导读和使用说明可以在站内阅读，第三方文章默认不复制全文。

产品保留从产前发现到出生后评估、治疗经历、支具生活和长期随访的主题覆盖；不再建设原计划中的全流程医疗业务平台。阶段是资料分类，不是对某位读者规定必须完成的检查或治疗路线。

## 2. 已确认的前提

- 个人开发和运营，没有医疗专业背景或执业资格，AI 用于辅助开发不能替代真实运营责任。
- 中国大陆部署，计划以个人主体办理备案；实际归属省份尚未提供，全国是受众范围。
- 同时保留 Web 与微信原生小程序，采用 Spring Boot 体系，首选 Halo。
- 首版资料由运营者逐篇筛选并手动录入，发布前核对来源、链接和介绍内容。
- 公众 RAG 后续再评估开发；后台 AI、DeepSeek、腾讯知识库均不是首版上线依赖。
- 不收集访客病历、检查报告、遗传资料或儿童治疗记录，不开放论坛、评论、私信和用户投稿。

这些是本次用户选择与项目范围，不是宣称其他个人必须采用同一方案。

## 3. 用户能完成的事

一个刚拿到超声提示的读者，可以选择“刚发现”，看到少量入门资料及各自来源；想继续了解出生后过程时，可以进入对应专题；看家庭故事时，能识别这是某个家庭在某个时间点的个人记录。

首版交付结果是“找到值得阅读的原始材料并知道来源”，不承诺确诊、判断预后、推荐具体检查、替代门诊沟通或消除焦虑。来源权威也不意味着每篇内容都适用于每个家庭。

## 4. 内容与栏目

| 阅读入口 | 主要收录内容 |
| --- | --- |
| 刚发现 | 官方入门资料、术语资料入口、站点阅读方法 |
| 产前了解与等待 | 相关机构资料、研究入口、就诊沟通的一般整理方法、家庭经历 |
| 出生后评估与治疗 | 机构公开资料、治疗过程介绍的原始出处、经历链接 |
| 支具与日常生活 | 相关资料、生活记录、复查与照护主题的原始信息入口 |
| 长期随访与预后 | 研究题录、随访资料、注明观察时间的家庭故事 |

资料同时按“机构资料、论文题录、家庭经历、本站原创”分类。原文包含专业观点时，介绍重点说明材料讨论什么及其背景，不由个人编辑进一步推导读者应如何诊疗。

站内另有搜索、专题、关于本站、来源说明、隐私说明、版权与勘误联系方式。搜索是站内资料卡检索，首版不搜索互联网全网，也不生成答案。

## 5. 双端安排

Web 是完整知识导航入口，支持浏览、搜索、资料卡详情和直接前往合法原站。优先做好手机浏览体验，兼顾电脑阅读与搜索引擎收录。

微信原生小程序展示同一份已发布目录、介绍和来源信息。它的外部网页、公众号文章和其他小程序入口有不同能力与条件，不能照搬 Web 任意跳转模式。逐类确认入口后再开放；暂不支持的来源应有清楚的题名与出处说明，不能显示一个实际不可用的“阅读原文”按钮。

双端共用内容数据与发布规则，界面按各自渠道适配。小程序类目、个人主体适用条件与阅读入口另设验证关卡，不把其通过审核作为已发生事实；若暂不能发布，Web 可以独立推进。

## 6. 技术与维护策略

采用 **Halo 社区版＋内容导航主题＋微信原生小程序＋必要的业务插件＋MySQL**。Halo 自带 Spring Boot 后端和管理后台，不再重复开发一套 CMS。主题页面与小程序读取同一份公开资料卡。

先验证已有分类、标签、元数据和搜索是否足够；需要补充时，集中在一个小插件中处理资料字段、公开输出和筛选。避免为了结构化卡片而深改 Halo 核心。

首版不维护独立向量库、Dify、RAGFlow、消息队列和搜索集群。部署、备份、域名与证书、内容核对、失效链接和投诉处理都由个人实际承担，需要留出持续维护时间。

## 7. 资料来源与版权策略

优先选择发布机构、期刊出版社、作者主页及合法开放仓储等原始来源。公开可访问不等于允许复制、翻译、截图、上传云平台或用于 RAG。

默认只记录必要题录和自己撰写的短介绍，使用自制或有明确许可的视觉素材，不抓取原文封面，不复制论文摘要、文章开头或全文。短介绍以介绍材料为目的，不能变成替代原文的详细复述。

手动收录减少了采集环节的复杂度，但不自动构成法律免责。发现盗版、明显侵权、误导性来源、原文撤回或有效权利通知时，应暂停入口并核查处理。第三方网站或付费代下取得的论文，不作为默认可公开或可上传云端的材料；应另找合法原始页面并核实使用范围。

法律依据与限制见[个人运营与版权边界](./个人运营与版权边界.md)，不把链接模式表述为已获许可或绝对安全。

## 8. 个人日常运营

每条资料遵循：发现候选 → 查明来源 → 手写介绍 → 分类与去重 → 核对公开范围 → 预览 → 发布。已发布资料定期复核链接与时效；纠错和投诉优先于增加收录量。

建议首批以约 20—30 条资料验证流程，每个阶段先有少量可用内容，不为填满栏目降低收录标准。数量是工作建议，不是既有成果或发布条件。素材不够时清楚显示暂缺，不生成虚构来源。

个人暂时无法维护时，可暂停新增收录；站点出现严重问题时能够停止相关资料的公开展示。对外说明真实维护状态，不承诺全天候医学答疑。

## 9. 项目成立与经营假设

当前按个人免费资料项目验证，不依赖付费医疗问答、医院采购、转诊佣金、支具销售或广告收入成立。没有已验证的用户规模、市场份额、机构合作、专业审核团队或商业收入。

主要成本是域名与服务器、备份、必要主题插件，以及持续筛选、核对和维护时间。采购前按真实访问量与实际报价编制成本，不在本计划中使用未经核实的云价格。

未来若引入广告、收费、专业内容服务或真实医疗合作，需重新评估经营主体、内容与行业条件，不能直接沿用免费导航站的判断。

## 10. 分阶段交付与验收

| 阶段 | 交付 | 进入下一阶段的依据 |
| --- | --- | --- |
| 当前：文档统一 | 计划书、需求、技术、版权规则、决策记录一致 | 当前范围明确，尚未开展本版开发 |
| 开发前验证 | Halo 资料卡、阶段筛选、双端公开接口和小程序入口验证 | 关键能力成立，必需插件及许可明确 |
| 首版建设 | Web 导航、管理后台适配、原生小程序页面、备份和撤回机制 | 真实资料可完成录入到阅读闭环，未泄露内部信息 |
| 发布准备 | 内容复核、备案与渠道核实、恢复演练、联系方式有效 | 对应渠道条件实际满足，不以代码完成代替 |
| 运行验证 | 小范围使用反馈、来源纠错与维护记录 | 个人能够持续更新，读者可以找到正确原始来源 |
| 后续 RAG | 单独立项与评估腾讯 ADP 等托管方案 | 有适当权利的语料、实际需求、账号及公开服务条件成立 |

不因主要由 AI 写代码就承诺固定完成日期。首版验收不要求开通模型、上传论文全文或开放生成问答。

## 11. 效果如何判断

优先观察读者能否在少量操作内找到匹配阶段的资料，是否理解来源类型，原文入口是否可用，以及运营者维护每条资料需要多少时间。记录失效链接、错误介绍、撤回和投诉的处理情况。

不通过收集健康档案或完整搜索词证明价值；不把页面浏览量、焦虑驱动的反复访问和无限收录量作为唯一目标，也不宣称网站已经改善医学结局。

## 12. 尚未完成的事项

尚未完成：实际备案归属确认、小程序类目及入口验证、Halo 主题与插件验证、资料权利清单、真实用户反馈和正式上线。本版为规划，不代表现有 OpenIsle 代码已经改造成 Halo 内容站。

原计划书中的论坛、家庭档案、报告解读、检查决策、机构服务、公众 AI 等模块暂缓；原始材料只作为需求研究和后续评估参考。当前范围变更以本版和配套技术文件为准。
