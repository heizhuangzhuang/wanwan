## 访问和现场核对

- [生产首页](http://81.71.123.100/xiaojiaoya/)和[支具随访大屏](http://81.71.123.100/xiaojiaoya/tools/brace-followup)使用当前 HTTP 站点。正式域名、HTTPS 及联系邮箱仍待配置或验收。
- Web 的应用用户、端口和反向代理保持现有部署结构。systemd 单元为 `wanwan-web.service`，发布目录为 `/opt/wanwan-web/releases/`，软链接 `/opt/wanwan-web/current` 指向当前版本。环境文件为 `/etc/wanwan-web.env`。
- 微信云托管环境为 `prod-d1gm7gr9e711335be`，服务名为 `xiaojiaoya`。当前 Web 使用该服务的 HTTPS 域名及 `/apis/api.xiaojiaoya.run/v1alpha1` 前缀。管理操作使用此项目的授权入口。

```bash
systemctl is-active wanwan-web.service
readlink -f /opt/wanwan-web/current
curl -fsS http://127.0.0.1:13000/xiaojiaoya/healthz
api='https://xiaojiaoya-331697-11-1510985006.sh.run.tcloudbase.com/apis/api.xiaojiaoya.run/v1alpha1'
curl -fsS -H 'X-Wanwan-Client: web' "$api/stages"
curl -fsS -H 'X-Wanwan-Client: wechat-miniprogram' "$api/resources?stage=JUST_FOUND&size=1"
```

上面的两条请求用于检查接口状态与来源标记。小程序真实链路仍需通过微信云托管通道验收。资料后端恢复后，Web 按现有配置实时读库。

## 云托管恢复与数据验收

1. 备份现有云 MySQL 和 Halo 持久化挂载，记录当前接流量的版本和可恢复点。把 `wanwan-cloudrun-mysql-0.1.6.zip` 用于同一服务的本地代码上传，Dockerfile 路径使用根目录 `Dockerfile`，端口 `80`。保留原库连接、持久化挂载和现有保密配置。入口脚本要求 MySQL 并记录选择的数据源。
2. 在新版本的预览流量核对 Halo readiness、插件启动日志和匿名 `/stages`、`/resources` 的 JSON。旧登记被 Halo 保留时，到受控 Console 核对插件版本、升级 JAR 并启用。出现问题时保留原流量版本。
3. 确认环境和数据源后，用[样本导入工具](../content/import-test-fixtures.mjs)通过授权的 Halo 管理 API 写入六条标记为「测试」的资料。Web 与小程序按「刚发现」阶段读取同一批资料，再重启测试版本复验。首批真实内容继续由运营者按出处和收录规则发布。
4. 在隔离环境恢复生产备份并对照撤回记录。在受控账号和手机上核对石膏记录隔离、删除和复诊提醒，核对附件及公众号入口、隐私指引和提审条件后再公开。

## 用户体验验收

开发者工具和自动化已覆盖跨午夜计时、午睡、重叠、历史计划和导出。真实家庭测试仍待执行。用虚构记录验证以下任务，记录任务是否完成、卡住位置和参与者的原话。

- 晚上开始，第二天结束，确认两个日期分别计入正确时长。忘记停止时能回到明细补改。
- 核对近 30 天和 10 年视图，能说出「无记录」「确认未穿」「低于目标」的区别。调整目标后仍能看懂历史结果。
- 在小程序生成 JSON，用 Web 还原并导出 Excel。核对每日、时段、计划和随访四组数据与原记录一致，并确认手机可分享文件。
