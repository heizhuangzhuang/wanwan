# ADR-005：前后端分离与微信云托管部署

状态：已采纳｜日期：2026-11-17｜取代：ADR-002 中的 Thymeleaf 主题与单机部署、ADR-004 中小程序直连方式

## 背景
运营者确认以下部署与二开边界：
1. 后端部署在**微信云托管（WeChat Cloud Run）**，同时向微信小程序与独立 Web 前端提供服务；
2. 仅通过插件 `plugin-wanwan` 与独立前端做业务扩展，**不修改 Halo 核心源码**；
3. **Web 部署在独立服务器**，运行轻量 Node 22 SSR 前端，通过 HTTPS + CORS 白名单只调用后端公开 JSON API（不再在 Halo 内维护 Thymeleaf 主题 `theme-wanwan`）。

## 决策
1. **后端（微信云托管）**：
   - 使用 `deploy/cloudrun/Dockerfile` 基于 `halohub/halo:2.27.3` 自动构建镜像并同步 `plugin-wanwan` JAR。
   - 最小实例数固定 **≥ 1**（防止冷启动超时与内存搜索索引重建延迟），挂载 **CFS 文件存储** 到 `/root/.halo2`，连接云托管 MySQL 8.0。
   - 新增原创导读公开接口 `GET /apis/api.wanwan.run/v1alpha1/posts` 与 `/posts/{name}`（只读取 `releaseSnapshot`，绝不泄露草稿）。
   - 通过 `WanwanCorsFilter`（实现 Halo `BeforeSecurityWebFilter`）在 `/apis/api.wanwan.run/**` 实施严格 CORS 白名单（环境变量 `WANWAN_CORS_ALLOWED_ORIGINS`），拒绝 `*` 通配符与非白名单跨域预检，仅允许 `GET / HEAD / OPTIONS`。
2. **Web 前端（独立服务器 `web/`）**：
   - 采用零第三方运行时依赖的 Node 22 + TypeScript 轻量 SSR 服务，输出服务端 HTML（保 SEO、移动优先、安全转义与 `Cache-Control: no-store`）。
   - 前置 Nginx 终止 HTTPS 与限流（`deploy/web-server/nginx.conf`）。
3. **微信小程序（`miniprogram/`，Phase 2）**：
   - 优先使用 `wx.cloud.callContainer` 直连微信云托管内网（`X-WX-SERVICE`），保留 `wx.request` 作为本地调试回退。
   - 平台资质与类目审核要求不变（P0 先行验证）。

## 后果
- 撤除 `theme-wanwan/` 与插件内主题路由，避免同一仓库维护两套 Web 渲染链路。
- 云托管开启公网域名供 Web 使用时，须在网关层限制公网只放行公开读取接口，后台 `/console` 单独控制访问。
