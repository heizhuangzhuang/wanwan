# ADR-001：资料卡使用插件自定义模型

状态：已采纳｜日期：2026-11-17｜取代：技术架构 v5 §4.1 "Post＋元数据首选"

## 背景
资料卡是强结构化对象（外部 URL、来源、DOI、访问条件、入口类型、链接状态、阶段多选），正文只有 1~3 句自写介绍。v5 首选用 Halo Post＋annotations 表达，插件为备选。

## 决策
- 外部资料卡：插件定义 Extension `ResourceCard`（`wanwan.run/v1alpha1`）。
- 专题：插件定义 `Topic`，保存导读文字与有序的资料卡名称列表。
- 本站原创导读：Halo 原生 Post。
- 阶段：5 个固定值作为枚举 `Stage`，首版不做可配置。
- 内部记录（许可凭据、投诉）：首版不进系统，使用私有离线台账。

## 理由
1. 强类型 schema，可校验、可建字段索引，按阶段/类型/状态筛选直接可用。
2. 泄露面最小：Post 自带文章路由、RSS、站点地图、评论与核心公开 API，撤回必须逐一覆盖；自定义模型只暴露插件主动提供的路由。
3. 富文本编辑器对短介绍无收益。

## 代价
需要在插件 `ui/` 中开发资料卡与专题的 Console 编辑页（Vue 3），估算 1~2 周。

## 停止条件
若实现资料卡闭环需要修改 Halo 核心，停止并评估 Spring Boot 3 自建精简后端。
