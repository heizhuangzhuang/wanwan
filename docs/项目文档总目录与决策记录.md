## 主要决策变化

| 阶段 | 当时方向 | 当前处理 |
| --- | --- | --- |
| 原始GitHub计划 | 从产前到长期随访的支持平台 | 保留需求研究，缩小个人实际服务范围 |
| BBS与AI方案 | Web、小程序、论坛与论文RAG | 论坛取消，公众RAG独立评估 |
| OpenIsle开发阶段 | 复用论坛并增加论文与AI模块 | 用户已要求停开发，代码保留作历史，不继续实施 |
| v2.0 | 展示与搜索，RAG仅后台 | 保留为路线A，不解释为法律唯一可行路线 |
| v3.0 | 个人条件下评估公众RAG可能 | 同时研究私人RAG、公众证据检索及有条件公众生成 |
| v4.0 | 先做资料与经历内容站，保留 Spring Boot、Web 和原生小程序 | 推荐 Halo 主题与公开内容 API；公众 RAG 延后，后台 AI 不作为首版依赖 |
| v5.0 | 手动精选的阶段式知识导航 | 题录＋独立简短介绍＋合法原文入口，搜索仅查本站公开信息；统一更新计划、需求、架构与版权文档 |

## 原项目需求的当前处置

| 原需求组 | 当前处置 |
| --- | --- |
| 从产前发现到长期随访的全过程主题 | 保留为阅读分类与资料专题，不做自动诊疗路线 |
| 论文、机构资料和家庭故事 | 优先收录合法原始入口及独立介绍；第三方全文、摘要和配图不默认搬运 |
| 网站与小程序 | 保留双端；共用资料，原文入口按各自能力验证 |
| 私人档案、家庭授权、检查任务与就诊包 | 不进入首版，不收集真实健康记录 |
| 论坛、投稿、评论、私信 | 不进入首版，手动精选不等于开放用户发帖 |
| 公众论文 RAG、模型接入与语义检索 | 后续独立评估；腾讯优先候选，当前不采购或上传论文 |
| 医生合作、会诊、预约、诊疗承接 | 无实际合作证据，不展示相应服务或背书 |
| 融资、付费医疗、广告和转介商业模式 | 不作为当前个人免费导航项目成立前提 |
| 来源核对、内容撤回、纠错、恢复和维护 | 必须落实，按当前需求和技术文件验收 |

## 本轮明确修正的判断

- 不能把论坛说成全国一律禁止。
- 不能仅凭历史医疗保健信息审批文件，认定原审核同意书目前仍适用于全部相关网站。
- 不能将医疗科普平台账号规范简单扩张为个人不得讨论任何健康经历，也不能假定独立站完全不受约束。
- 后台AI是保守产品路线，不是个人公众RAG在法律上必然被禁止的结论。
- 腾讯托管、平台审核或模型备案不能替项目整体承担内容与运营责任。
- 专业人士核对来源、审核固定内容和审核实时生成结果不能混为一项。
- 面向全国与个人备案主办者所在地是不同概念。
- 手动精选、标题加链接和短介绍都不自动免责；链接服务条款需按实际行为和条件判断。
- 小程序请求本站 API 与打开第三方原文是不同能力，Web 的外链体验不能直接承诺给个人小程序。
- 已发布资料卡可展示，不代表其链接的全文可以复制、上传云端或用于 RAG。
