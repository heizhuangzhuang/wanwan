# 小脚丫家庭记录双端测试设计

2026-11-25 · 测试范围覆盖现状回归和[下一版开发设计](./家庭记录双端开发设计.md)。下表 T01–T16 是待实现功能的验收规格。现有测试的实际执行结果单列在末节。

## 1. 开发前准备

- 建立独立测试站点和 MySQL 库，使用与项目锁定版本一致的 Halo、两个插件实例或等效的跨进程并发环境。微信登录与订阅提供可控制成功、拒绝、延迟和超时的替身。真机体验版单独使用测试账号和测试模板。
- 家长 A 有旧石膏档、手动支具云备份及一段未结束的本机计时。家长 B 使用同一台电脑但属于另一账号；另建一名已停用家长和一名运营者。准备两台浏览器、iOS 与 Android 微信、旧版客户端，以及空库、有旧数据和已迁移三份基线。全套使用构造数据。
- 固定当前时间和业务时区 Asia/Shanghai。准备带不同会话、乱序请求、超时回放的接口夹具。数据库以业务条目数、版本、操作回执和提醒任务数为判据；界面文案作为第二判据。计时基准用绝对时间校验，跨日总量可独立手算。
- 在首次开发提交前固定状态码、错误码、配对有效期和退出规则。短码参数尚未上线，过期测试使用可控时钟和实际配置值 TTL 验证边界。以下“失败”指断言未满足，不是允许用户绕过流程的替代操作。

## 2. 功能与异常用例

| 编号 / 层级 | 前置与步骤 | 可观察的通过条件 |
| --- | --- | --- |
| T01 P0 双端界面 | 匿名访问分享文章、搜索、工具说明、公开清单；关闭身份服务再访问。进入个人历史后取消登录。 | 资料服务正常时两端可读可下载，网络轨迹没有私有档案请求；个人历史不显示，取消回到原位置，没有创建计时或空档案。 |
| T02 P0 身份集成 | 同一微信同时首次登录两次。在创建 Halo 用户后、绑定提交前让一次请求中断，再重试。已有绑定另起一个非管理员账号测试。 | 同一微信只有一个可用 Halo 普通用户和一个绑定，原有用户恢复原档；不按昵称归并、无 Console 权限。 |
| T03 P0 配对 | 两个浏览器各生成挑战；手机只确认其一。分别在 TTL 前一刻、恰好到期、到期后兑换；再测取消、重复兑换、确认后网页刷新和连续输错码。 | 只有发起且已确认的浏览器得到会话；到期或取消失败；同一挑战至多发一份会话；重试或重新配对可恢复。达到配置的错误次数或频率后限流。 |
| T04 P0 权限集成 | 用 B 的会话读取、改写、删除、导出 A 的测试记录。A 登出 Web 后在小程序读自身档案，再停用 A 后从两端读取；分别试家庭用户的普通密码和重置入口以及运营者正常登录。 | 越权请求均未泄露记录且数据库未变。单端登出只撤销该端；账号停用后两端请求均拒绝。家长不能通过其它认证入口绕过微信策略，运营者正常使用后台。 |
| T05 P0 授权与导航 | 首次扫码后拒绝支具授权，再单独同意石膏；取消微信提醒。确认登录后停留计时页 5 分钟才点开始。 | 各项授权独立，有原授权的老用户按版本复用；能记石膏，不上传支具档；计时从点击开始算，等待的 5 分钟不计。 |
| T06 P0 计时并发 | A 两端同时开始；再用两端结束同一 T。开始新时段 T2 后，送达旧设备延迟的 stop(T)。两服务实例并行执行。 | 每档最多一个活动计时；T 只落一条结束记录。T2 仍在运行，双方刷新得到相同起止与统计。两个同时离线的开始补传后，冲突的一方保留候选供核对。 |
| T07 P0 持久性 | 模拟业务写入前失败、事务中退出、提交后丢回包。客户端重开，用相同 operationId 重发；再用该编号提交不同正文。 | 成功事务中业务变更及回执均存在，失败事务均不残留。相同重试得到原结果、一次写入；不同正文返回 409。只有得到确认后显示「已同步」。 |
| T08 P0 离线与换号 | A 离线新建石膏或开始并结束计时，杀进程后 B 登录，再换回 A 联网。另外模拟本机配额耗尽、登录过期和数据库短时不可用。 | 成功写本机的草稿和操作在重开后仍在；B 的列表、导出、队列看不到 A。写本机失败有明确提示、不显示已保存；失效时暂停并要求同一人登录，补传后只出现一份。 |
| T09 P0 旧档识别 | 导入旧石膏密文和支具密文，分别配正确或旧索引密钥、缺旧索引密钥、缺解密密钥、错误归属映射。 | 正确样本按原 owner 找到并解密；预期存在但验证失败时停在待恢复，原密文仍在，不把异常当作空档，不读入另一家庭。 |
| T10 P0 本机导入 | 为旧 HTTP 来源、旧小程序键/双槽及旧云档构造含时段、计划、零时长确认日、随访、观察、问题和 activeStart 的备份。同 ID 同内容导入两次；同 ID 不同内容再导入。 | 新 HTTPS 站可通过旧来源本地导出→新站预览→确认导入恢复；归属需家长确认。各类计数和 activeStart 完整，旧文件可导出。重复导入不增条，有冲突保留两份待核对。 |
| T11 P1 时间与输入 | 北京时间 23:55 开始、次日 00:15 结束；两设备分别设不同时区。再测相邻时段、零时长、倒拨和离线重叠；旧目标跨日重跑迁移。 | 分日分别为 5 和 15 分钟，合计 20；相邻端点无双计，结束不晚于开始或重叠时保留输入并提示核对。旧目标迁移生效日不随重试改变。 |
| T12 P1 容量与损坏 | 旧云 archive 字符串测 2 Mi 字符上下与等值，外层正文测 4 MiB 字节上下与等值，含中文。对旧客户端本地限制测边界，另测不完整 JSON、未知文件版本、批次中断后再导入。 | 记录具体在哪一层拦截。合法大文件以新批次途径导入；非法或超限明确提示，不出现半批可见、空档替换或原件被移除。重试后逐项校验。 |
| T13 P0 石膏与提醒 | 两端同时编辑一条，另端删除后再提交旧编辑。复诊改期且拒绝重新订阅；模拟旧任务已领取、微信超时、旧任务回写时出现新任务；跨版本切换时触发到期任务。 | 显示并保留冲突，删除的条目未被复活。改期使旧待发任务失效，拒绝订阅仍保存日期。仅有效授权安排新提醒；发送未知可见，禁止自动补发或旧回写影响新任务。 |
| T14 P0 撤回和迁移竞态 | A 离线有待传操作，另一端清空并撤回后重新授权，再补传旧操作。同时测试冻结瞬间，旧客户端上传整档或执行清除，新客户端写入。 | 档案世代拒收撤回前的队列；每段迁移时间内最多一个写入方。冻结前成功写的记录在核对结果中，冻结后旧操作不会覆盖新版，旧客户端得到可操作提示。 |
| T15 P0 恢复演练 | 建立两个测试档案、一个活动计时和一个未发提醒，持久库备份至隔离环境并按密钥版本恢复。服务重启、撤销后的队列重连和已停用会话再次访问。 | 样本能解密、起止与家长归属正确，撤回或禁用操作不会因恢复旧快照而失效（对备份点后的撤销先重放或封锁访问）；隔离环境未发真实消息。未证明持久库或密钥可用时不启用家庭写入。 |
| T16 P0 浏览器及真机 | 用同一设备两账号前后登录，走返回键、刷新、首屏 SSR、导出、后台切前台及扫码取消；查看公共缓存、统计样本、站点地图、响应头。体验版验证同手机配对。 | 不出现上一家庭的页面、下载链接或统计内容；私有响应 no-store，Cookie 通过 HTTPS；公开页面可用。iOS 与 Android 都能完成授权和返回目标，注销后不能从旧页面重取私人数据。 |

石膏边界样例同时用于 T07、T13。用第 99、100、101 条区分现有保存和新增；备注测 299、300、301 个常规字符，侧别、序号和日期沿用既有合法值校验；提醒时间测正好未来 120 秒、刚超过 120 秒、未来 90 天整及刚超 90 天，注入固定时钟。有效记录的保存与提醒能否安排应分别断言。

## 3. 测试执行顺序与交付证据

1. **接口实现前**，测试负责人把 T01–T05 的账号和页面矩阵及 T06–T15 的固定样本交给开发。开发先用替身接通页面，验证登录取消、冲突和「待同步」状态；同一命令结构在两端复用。
2. **每次提交**，用单元测试覆盖日期、备份转换、授权与状态转换。接口测试向两个实例提交相同和不同操作，保留数据库前后计数、版本和回执。单机 mock 不能作为并发放行证据。
3. **灰度前**，执行全部 P0 和时间/容量边界。交付构建版本、用例编号、实际结果、匿名追踪号和缺陷链接。账号串读、已确认数据丢失、重复计时、旧档覆盖、备份无法恢复或未处理的隐私泄露都阻断新版开放。P1 失败时评估并记录受影响的功能，相关迁移或统计入口不得带已知数据损坏风险启用。
4. **回退演练**，停止试点新写，保留测试库新增操作，让旧客户端只读；用隔离副本验证新数据可导出重放，再决定恢复写入。发布记录区分“已用替身验证”“集成通过”“微信真机通过”和“未验证”。

## 5. 第一阶段实现验证

本地构建与自动化回归通过。微信小程序 62 项，Web 9 项，Halo 插件 71 项，Console 前端 3 项。

在隔离的 Halo 2.27.3 与 MySQL 26.7 环境安装并启用插件。使用预置的合成微信身份和两端会话，实测同账号从小程序端开始计时，由 Web 与小程序并行结束时一个请求成功、另一个返回 409，数据库只保留一条时段。另验证了双端读取同一石膏条目、另一账号读到自己的空档、匿名读取公开阶段列表、私有接口拒绝未登录请求及 Console 家庭账号列表的访问权限。

这次集成覆盖单个 Halo 实例。真实微信扫码、双实例压力测试和备份恢复演练仍待执行。
