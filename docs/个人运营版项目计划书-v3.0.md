# 弯弯：个人运营与分阶段公众 RAG 项目计划书

版本：3.0｜2026-11-12｜状态：方案评审，尚未批准公开 AI 上线或恢复代码开发。

> 历史计划，不作为当前执行依据。最新方案见[当前项目计划书](./项目计划书.md)、[产品需求与内容规范](./产品需求与内容规范.md)、[技术架构与实施方案](./技术架构与实施方案.md)。用户已确定手动精选录入，以题录、自写简短介绍与合法原文入口建设知识导航；保留 Halo / Spring Boot、Web 与原生小程序，公众 RAG 后置。以下三条 RAG 路线及静态站建议保留历史语境，不能继续作为首版采购和开发依赖。

本版与[综合评审 v3.0](./个人运营与公众RAG可行性综合评审-v3.0.md)共同阅读。原计划书、v1.0和v2.0保留为历史，文档关系见[总目录](./项目文档总目录与决策记录.md)。

## 1. 项目定位

由个人以家长、资料整理者身份，围绕孕妇与家庭的资料查找和就诊沟通准备建设信息工具。初期聚焦足内翻相关需求，面向全国读者，但不预设已经具备全国医疗服务能力。

RAG 是希望保留的能力：先帮助运营者检索和整理资料，进一步研究向公众提供受控资料检索或生成问答的可行性。是否能够公开、能回答什么，依据实际业务和验证结果决定，不由“采用哪家云服务”单独决定。

用户没有医疗专业背景或执业资格；尚未提供真实医学审核、医院合作或诊疗承接条件。AI辅助开发不替代这些条件。

## 2. 核心用户任务

读者应能找到真实来源，分清原始资料、个人经历、固定编辑内容和AI生成内容，知道材料没有回答什么。准备就诊时，可以参考一般资料整理方法，保存自己要向接诊团队询问的问题。

项目不把持续焦虑、长时间刷页或AI调用次数当作价值。要验证的是减少查找困难和来源混淆，而不是声称改善了尚未实际测量的医学结局。

## 3. 三项候选产品

### A. 先启动：私人 RAG 与公开展示站

运营者在腾讯 ADP 等托管平台使用授权资料检索、做笔记和整理草稿。网站展示经过核对且公开范围明确的资料入口、论文题录、一般整理方法和真实个人经历。

这条路线便于个人起步，也便于检测资料处理效果。但后台生成的文本不能自动公开，编辑核对不能冒充专业医学审核。

### B. 优先核实的公众升级：证据检索

读者使用关键词或自然语言找到已发布资料卡、原始链接、适当授权的短摘录和固定内容。检索范围只包含允许公开的集合。

该功能主要是检索，不应为了营销而宣称能够现场给出医学判断。它仍有内容与权利要求，但比无限制生成新的专业医学结论更便于界定维护范围。

### C. 保留可能：公众 RAG 生成问答

独立评估个人主体的实际登记与渠道路径、平台合同条件、输出范围、专业参与、数据保护和费用控制。首先比较资料与站点使用等窄范围辅助，以及专业医学解释；不能把二者混成同一审批问题。

当前没有批准开放医学咨询型即时问答。保留此路线表示开展可行性研究，不表示已经通过法律、合同或质量验收。

## 4. 内容体系

资料按首次发现、复核与等待、就诊准备、出生后和生活支持等主题组织。主题不是平台给用户制定的医疗路径。

资料对象保存题名、作者或发布者、年份、原始链接、材料类型、许可记录、核对日期、版本和AI参与记录。公开与内部研究集合分别维护，不把私人知识库全部导出为网站搜索数据。

对专业医疗内容，先核实具体发布与审核路径；对原文使用，核实允许的处理和展示范围。付费下载、开放获取和可以阅读不自动具有相同的再使用权限。

## 5. 技术选择

公开展示部分优先采用Vue/Nuxt静态站与公开搜索索引。RAG首先验证腾讯ADP，阿里云百炼等作为技术备选，不并行建设多套必须维护的知识库。

只有在明确公众生成或动态管理需求后，再决定是否使用Spring Boot或云函数作为服务端。首版不因之前讨论过论坛，就继续采购论坛数据库、Redis、消息队列和搜索集群。

平台选择依据是：个人账号实际适用、资料解析与来源可查、公众与私有范围可隔离、数据和费用可控、能够迁移及处理撤回。供应商的品牌或案例不能替本项目完成这些判断。

## 6. 运营工作

个人需要持续处理来源核对、内容版本、失效链接、公开错误、费用和访问异常。一次AI生成或两模型交叉评价，不能代替真实专业参与。

若开放公众生成，额外评估用户越界提问、健康信息输入、投诉、撤回及输出审核安排。不能先承诺即时回答，再以无法持续执行的专业审核流程支撑宣传。

不收集用户病历、遗传或儿童治疗记录作为当前首版功能。暂缓论坛、评论、私信、家庭协作、提醒和正式医疗服务，避免把独立复杂产品线并入RAG试验。

## 7. 经营安排

现阶段不依赖融资、机构采购、付费医疗问答、检测转介或商品营销成立。成本评价包括托管和模型费用，也包括资料许可、专业审核和个人时间。

免费不等于免除责任，注册公司也不自动取得医疗或AI相关资格。如果未来确有商业或专业合作需求，按真实业务重新设计主体与责任，不通过挂名、借证或隐瞒用途处理。

## 8. 无代码验证计划

1. 从原计划选约10个真实想解决的问题，写出希望用户看到的结果，区分资料定位、固定内容、一般生成与个体健康判断。
2. 使用具体样例向腾讯核实个人账号、专业内容、平台内分享与自有站集成的条件，保留明确答复。
3. 明确主办者实际备案所在地；受众全国不改变这一输入的必要性。按实际公开功能核实备案与其他适用事项。
4. 用20—30篇有适当权利的代表资料测试引用、解析、拒答、删除、导出和人工修正耗时。
5. 决定实际采用A、B还是满足条件的C。没有得到必要证据前不恢复完整系统开发。

## 9. 继续、调整与停止条件

私人RAG能减少资料整理时间、且公开内容有明确边界时，可以继续A。公众仅需要找资料而非新结论时，优先推进B。

若C的主要价值依赖持续医学解释，而个人无法落实专业参与和公众发布条件，应保留内部工具，寻找真实合作或缩小服务范围，不能把腾讯接口当作补齐条件的证据。

若资料处理错误、来源许可不清或个人无力纠错，则暂停受影响的内容或功能。过去已写出的代码和文档数量不作为继续投入的理由。

## 10. 当前状态

完成了原项目资料归档、文档对照与公开规则、合同研究。尚未完成实际账号验证、监管或平台书面确认、资料权利清单、医学审核、真实用户测试及公众上线。

本版保留公众RAG的可行性研究目标，但不宣称已经存在能够自动规避个人运营困难的供应商或技术方案。
