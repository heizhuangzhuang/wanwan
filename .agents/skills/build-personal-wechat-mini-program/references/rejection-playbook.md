1. 先保留原始证据

## 1. 先保留原始证据

收到拒审或处罚后保存：

- 平台原文、规则编号、截图、时间、版本号；
- 审核时提交的代码 commit、构建产物和审核资料；
- 当时 MP 后台类目、隐私、备案、域名和资质配置；
- 审核测试账号、远程配置和服务端响应；
- 线上/体验版对应页面录像和日志；
- 与同类历史版本的差异。

不要先覆盖版本或改后台再取证。复制 `assets/rejection-postmortem.md` 建立复盘。

## 2. 根因分析

把拒审原文拆为：

```text
规则域
  -> 审核观察到的现象
  -> 命中页面/账号/数据/配置
  -> 直接原因
  -> 系统性根因
  -> 影响范围
  -> 修复与防复发验证
```

示例：

```text
“功能不完整”
  现象：按钮无响应、空白页
  直接原因：体验环境 API 域名未配置
  系统根因：CI 只在 urlCheck=false 的工具环境测试
  修复：配置正式域名、关闭跳过校验、真机弱网测试
  防复发：CI 扫描 urlCheck + 体验版冒烟测试
```

不要把审核文案当唯一根因。一个“类目不符”可能来自主体、页面内容、隐藏功能、支付、备案或简介不一致。

## 3. 高频拒审映射

| 拒审主题 | 重点调查 | 典型根因 |
|---|---|---|
| 类目不符 | 实际功能、主体、资质、备案标识、首页入口 | 用宽泛类目包装受监管服务；隐藏类目；个人范围不支持 |
| 功能不完整 | 所有按钮、空状态、错误、登录、权限、隐藏/付费功能 | 测试版、空白页、域名错误、审核账号不可用 |
| 简介/信息不一致 | 名称、Logo、简介、类目、页面 | 简介只写愿景；搜索词堆砌；Logo 混淆官方 |
| 隐私声明不一致 | API/组件、SDK、后台指引、触发时机 | 未声明接口、声明过多、冷启动索权、无删除 |
| 诱导分享/订阅 | 文案、奖励、解锁、弹窗频率 | 分享后继续、订阅领奖、概率/延迟收益 |
| 无实质服务 | 首页和核心闭环 | 只有二维码、广告、跳转、客服消息或一个按钮 |
| 支付违规 | 商品类型、主体、支付通道、回调、外部引导 | 普通个人接支付；虚拟商品外部充值；个人收款码 |
| UGC/内容安全 | 发布前检测、人工复核、举报巡查 | 只做客户端敏感词；头像/昵称/图片漏审 |
| 侵权/混淆 | 商标、字体、图片、明星、官方名称 | 无授权；模仿微信/政府/品牌 |
| 稳定性/UI | 崩溃、卡顿、返回、弹窗、自动播放、广告 | 只测模拟器；弱网失败；广告遮挡功能 |
| 备案问题 | 名称、负责人、联系方式、服务内容 | 信息变化未变更；备注与实际服务不一致 |

### 类目不符

逐项回答：

1. 当前主体路线是什么？
2. 每个真实服务是否在当前官方个人类目范围？
3. 是否需要个人无法提供的牌照、企业资质或认证能力？
4. 类目页是否真实可达并能使用，不只是介绍？
5. 首页、简介、备案服务内容和审核备注是否一致？
6. 远程配置、账号角色、地域和时间是否展示不同服务？

若核心业务不开放，不要通过删截图、改标题或临时关入口重提；改主体或改产品。

### 隐私不一致

生成对账表：

| 源码 API/SDK | 个人信息类型 | 触发页面 | 后台声明 | 隐私政策 | 拒绝降级 | 删除方式 |
|---|---|---|---|---|---|---|

修复代码、后台和文案三处，不只更新一处。

### 功能不完整

覆盖：

- 首次启动、空数据、未登录、权限拒绝、弱网；
- 所有类目入口和按钮；
- 审核账号的角色、会员、付费、历史数据；
- 域名/TLS、环境配置、后端白名单；
- 返回、退出、注销、投诉和售后。

## 4. 整改与验证

按以下顺序：

1. 修复主体/类目/资质等路线问题。
2. 修复代码、服务端、后台配置和数据。
3. 删除真实无用功能，而非只隐藏。
4. 更新名称、简介、隐私、备案和审核材料。
5. 为根因补静态规则、自动化、真机用例或运营流程。
6. 用与审核相同的账号、体验版、远程配置和时间条件复测。
7. 对不同 IP、地域、账号和版本做差分，确认没有审核对抗逻辑。

记录每项：修改文件/配置、验证命令、真机、截图/录像、预期和实际。

## 5. 再提交说明

使用事实式表达：

```markdown
上次拒审：隐私声明与实际调用不一致。

根因：`pages/profile/index` 在用户点击上传头像时调用 `chooseMedia`，但后台未声明“相册/摄像头选择的照片或视频”；同时旧版在页面 onLoad 提前申请相册权限。

本次修改：
1. 删除 onLoad 提前申请，只在用户点击“选择头像”后调用；
2. 在后台隐私保护指引补充对应信息类型、用途和保存期限；
3. 增加拒绝授权后的手动默认头像路径；
4. 增加账号删除入口并验证对象存储清理。

验证路径：首页 → 我的 → 编辑资料 → 选择头像。
测试账号：……
验证结果：同意、拒绝、撤回和低版本路径均已真机通过。
```

避免：

- “已全部整改，请尽快通过”；
- “同行都这样做”；
- “只是审核员没看懂”；
- 与真实代码不一致的排除声明；
- 长篇情绪化解释。

## 6. 申诉

仅在以下情况考虑申诉：

- 审核事实明显识别错误；
- 已有有效官方类目/资质/授权，审核未识别；
- 规则适用对象混淆，例如普通个人、服务商代认证、个人升级版；
- 平台能力或后台状态与审核结论矛盾；
- 处罚涉及已修复或并不存在的版本。

申诉包包含：

- 一页结论；
- 平台原文与争议点；
- 官方 URL、核验日期和短原文；
- AppID、主体、类目、资质、备案证据；
- 可复现路径、测试账号、录像、日志；
- 版本 commit、发布时间和配置；
- 请求平台复核的具体问题。

不要引用 AI 生成运营分 DOCX 中的“5 日一次申诉、48 小时反馈”等数值，除非当前官方页面/后台再次确认。

## 7. 禁止做法

- 审核时关闭、通过后开启核心功能。
- 针对审核账号、腾讯 IP、地域或时间展示合规版。
- 使用伪造资质、借用类目、空壳页面。
- 把违规服务迁到 H5、其他小程序、公众号、个人号或客服消息。
- 反复无实质修改提交，消耗审核资源。
- 删除平台投诉入口、拦截返回、闪退或闪屏规避检查。
- 把“过审”作为安全、合法或长期可运营的证明。
