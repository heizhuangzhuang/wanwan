## 1. 注册、认证与备案的关系

分别建模：

- 账号注册/实名：创建 AppID 和确定主体。
- 微信认证：核验账号主体与信息，影响部分能力；不同注册渠道和主体适用范围不同。
- 小程序备案：向电信主管部门履行移动互联网应用备案。
- 服务类目/资质：说明实际服务并提交平台或法律要求材料。

不能用其中一个替代另一个。账号已实名不等于已备案；备案通过不等于获微信认证；微信认证不允许把主体直接换成另一个人或企业。

## 2. 个人备案

官方备案指引当前流程：

```text
备案信息填写
  -> 平台初审（页面称通常 1–2 个工作日，以实际为准）
  -> 工信部 12381 短信核验（24 小时内）
  -> 省通信管理局审核（页面称 1–20 个工作日，以实际为准）
  -> 下发备案号
  -> 发布后在更多资料页展示
```

### 个人材料与字段

- 当前支持的个人有效证件；
- 证件正反面、姓名、号码、住所、有效期；
- 实际通讯地址；
- 本人手机号、验证码、应急手机号、邮箱；
- AppID、小程序名称；
- 备案服务内容标识；
- 20–200 字真实服务说明；
- 前置审批/专项审批和地方补充材料（如适用）；
- 管理员/负责人刷脸核身；
- 在线确认承诺书和平台生成的真实性核验单。

提交当天以页面为准核对图片大小、分辨率、水印、证件有效期和地方要求。

### 个人路线阻断

官方本地备案快照写明个人主体不可选择经营性性质、企业/单位性质、涉及前置审批的服务内容。若实际业务涉及出版、网络视听、药品/器械、文化、新闻、网约车、校外培训、宗教、互联网金融等，先判断是否必须换主体，而非尝试填写更宽泛备注。

### 短信核验

- 留意主体负责人和小程序负责人手机。
- 12381 短信收到后 24 小时内到工信部系统核验。
- 页面称验证码错误/无效可触发一次重发；超时会自动驳回并需重新提交。
- 平台初审和管局时长只作估计，不向用户承诺 SLA。

### 变更与注销

名称、负责人、主体名称、主体负责人、联系方式等变化时及时判断变更备案。主体统一社会信用代码变化、主体注销/吊销/撤销等异常时，可能需要注销后重新备案。

## 3. 提审前一致性

形成一条可追踪链：

```text
真实主体与资质
  = 实际功能/内容/商品/变现
  = 微信服务类目与标签
  = 备案服务内容与说明
  = 名称/简介/Logo
  = 首页入口与类目页面
  = 隐私保护指引
  = 审核备注与测试账号
```

重点检查：

- 名称、Logo、简介相互关联，无官方混淆、侵权、绝对化和营销堆词；
- 核心功能首页可发现；所有类目页面直达或经过不超过合理步骤；
- 不存在审核员专供版、地域/IP/账号差异化或审核后远程开启；
- 无“测试、开发中、敬请期待、TODO、mock”等内容；
- 页面可打开、按钮有效、返回正常、弹窗可关闭、无自动播放；
- 登录、会员、付费和隐藏功能可由审核账号完整体验；
- 联系开发者、投诉、侵权、退款/售后、注销/删除入口有效；
- 广告不遮挡或中断核心流程。

## 4. 审核资料

复制 `assets/review-submission.md` 并填写。

### 审核备注

包括：

- 一句话说明小程序真实用途；
- 首页到每个类目核心页面的路径；
- 测试账号、密码、角色和验证码处理；
- 会员/付费/权限/特定时间或数据触发步骤；
- 数据和权限的具体用途、拒绝后的行为；
- UGC 内容安全、举报和人工审核路径；
- 资质、备案、授权和第三方内容证据；
- 本版本相较上次拒审的修改和验证。

不要在审核备注中写无法证明的“绝不收集”“无任何交易”“全部合规”。让备注与代码和后台配置一致。

### 测试账号

- 能体验所有角色和功能；
- 不依赖审核人员联系开发者临时开权限；
- 在审核周期内不失效、不锁定、不要求真实支付或敏感个人数据；
- 测试数据足以展示完整状态；
- 如平台首次提审没有测试账号入口，按官方流程在被打回后的入口补充，并在产品设计上仍提前准备。

### 类目页面

每个类目功能必须真实存在、可用、与类目一致。不要把类目页指向公告、空白页、登录墙、二维码或多次跳转后的外部服务。

## 5. 发布与更新

### 发布

1. 固定 release commit 与构建环境。
2. 运行测试、静态审计、包体和隐私差异。
3. 生成体验版，真机验收。
4. 上传版本并填写准确描述。
5. 提交审核资料。
6. 审核通过后确认发布，不把审核通过当自动发布。
7. 发布后验证正式版入口、备案号、域名、后台配置、监控和核心流程。

### 更新

官方更新机制说明：

- 用户可能继续打开本地旧版本；
- 冷启动会异步检查更新，新包可能下一次冷启动才应用；
- 使用 `wx.getUpdateManager` 在新版本准备好时提示重启；
- 正常全量发布后仍需要时间覆盖用户；
- 可在后台配置优先本地版本和最低可用版本。

因此：

- 服务端至少兼容一个合理旧版本窗口；
- 数据库迁移使用向前/向后兼容步骤；
- 严重不可用旧版再设置最低可用版本；
- 监控按 App 版本分组；
- 不在客户端 success 后立即删除服务端旧字段。

### 回滚

准备：

- 服务端功能开关只用于安全降级，不用于审核规避；
- 可回退的 API 和数据 schema；
- 紧急修复版本与审核说明；
- 旧版兼容、最低可用版本和用户提示；
- 事件时间线与复盘。

## 6. 流量主与营销

官方流量主公开条件于 2026-07-12 核验：

- 小程序累计独立访客 UV 达到 500 人及以上；
- 无刷粉行为且未曾有严重违规记录；
- 另有同公司主体继承条件；
- 开通后补充财务资料。

公开条件未排除个人主体，但应以当前后台入口为准。

个人流量主的结算与税务也需单独核验。腾讯客服当前说明个人通常无需向平台寄送发票，由平台按规则代扣代缴；其 2026 年起的扣缴方式及税务机关平台内从业人员规则都可能继续调整。Skill 只应给出留存身份证明、收入明细、扣缴凭证和咨询税务机关的流程，不提供个性化税率、起征点或“绝对免税”结论。

广告合规：

- 小程序必须有实质服务，不能是纯广告壳；
- 广告不自动弹出/跳转、中断缴费或主流程；
- 不遮挡按钮，不制造误触，不伪装功能按钮；
- 激励广告不得成为平台禁止的分享、订阅、下载或虚假奖励工具；
- 处理广告加载失败、关闭和未完成观看；
- 财务、税务和结算信息真实。

分享、订阅消息和营销：

- 不以分享/订阅作为核心功能继续条件；
- 不用现金、积分、概率或延迟收益强迫分享；
- 不骚扰、不下发与用户预期不符的消息；
- 不诱导下载 App、关注公众号、添加个人号；
- 活动规则、数量、期限、奖励和退款显著完整。

## 7. 持续运营与变更

建立月度/版本检查：

- 当前个人类目和能力有无变化；
- 备案、主体、负责人、联系方式是否一致；
- 资质、授权、证书、域名和 TLS 是否到期；
- 隐私声明与代码/SDK 是否漂移；
- 内容安全、举报、投诉、退款和售后是否闭环；
- 崩溃、错误、弱网、性能和旧版本比例；
- 广告、分享、订阅和客服是否被滥用；
- 云费用、存储、日志、备份和删除任务；
- 管理员、成员、代码上传私钥和服务商权限是否最小化。

对新增类目、收费、UGC、敏感信息、第三方 SDK、服务商或支付路线重新执行完整门禁。

## 8. 停运

普通小程序也应：

- 提前告知用户服务停止时间和影响；
- 处理未履行订单、退款、售后和投诉；
- 提供数据导出或合理迁移（如承诺过）；
- 注销/变更备案和关闭不再使用的域名、密钥、云环境；
- 立即停止使用并删除依法/规则不再允许保留的数据；
- 保留法律要求的最小交易/财务记录并限制用途；
- 防止废弃接口、存储桶和管理员账号成为安全入口。
