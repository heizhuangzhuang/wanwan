## 1. 性能预算

在开发前为关键路径设置可测预算，不制造官方不存在的统一阈值。至少记录：

- 主包、各分包和媒体资源大小；
- 冷启动、热启动、首屏可交互、核心页面切换；
- 关键 API P50/P95、超时率、失败率；
- 每分钟请求数、并发和重试；
- 页面节点数、长列表规模、setData 次数/数据量；
- 峰值内存、图片解码、视频和 Canvas 使用；
- 崩溃、JS 错误和白屏率。

预算以真实低端设备、典型网络和用户体验为准，并用开发者工具性能面板、真机调试和线上体验分析验证。

## 2. 启动与包体

官方 2026-07-12 的[分包加载](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html)页面指出：整个小程序全部分包总计不超过 30M，服务商代开发的小程序不超过 20M；主包和单个分包各不超过 2M。个人升级版属于服务商代开发路线时按 20M 预算。限制仍可能调整，最终以开发者工具和上传结果为准。

### 分包

- 按使用频率和业务边界拆分，而非按目录机械拆分。
- 主包保留启动页、tabBar、首屏必需组件和最小依赖。
- 活动页、低频设置、管理、媒体编辑等放入分包。
- 对独立且要求快速启动的场景评估独立分包。
- 使用分包预下载平衡首次进入延迟，不预下载用户大概率不会访问的包。
- 使用分包异步化剥离低频组件、插件和逻辑。

### 按需注入

- 评估 `lazyCodeLoading: requiredComponents` 等现行能力和基础库要求。
- 不在 `app.json` 全局声明只在一个页面使用的组件或插件。
- 避免副作用模块在加载时执行昂贵计算、网络或数据初始化。

### 资源

- 代码包只放小图标等必要资源。
- 大图片、音频、视频、字体部署到合规 CDN/对象存储。
- 压缩图片，按显示尺寸提供资源，选择合适格式。
- 避免 WXSS 内联大量 Base64。
- 清理 demo、测试数据、旧页面、Source Map、无用依赖和重复资源。
- 上传前检查实际构建产物，而非只看源码目录。
- `packOptions.ignore` 排除的文件不计入包体，但仍应纳入仓库密钥扫描；不要用忽略规则掩盖密钥或违规源码。

### 首屏

- 首屏只请求必要数据；其他内容延迟、分页或预取。
- 优先展示结构和可操作内容，局部 loading 代替全屏长等待。
- 缓存稳定配置和最近数据，但标记时间并设计失效。
- 避免启动时等待非关键登录、埋点、广告或多接口串行。

## 3. 运行时性能

### `setData`

官方建议：

- 只把渲染相关字段放入 `data`；
- 合并连续 setData；
- 使用路径更新具体数组项/对象属性；
- 不传整个 `this.data`；
- 避免毫秒级更新和在 `onPageScroll` 每次更新；
- 后台页面停止高频 setData；
- 将高频更新区域拆成独立组件。

审计高风险模式：

```js
this.setData(this.data)
this.setData({ hugeList: transformedHugeList }) // 每个小变化都传全量
onPageScroll() { this.setData(...) }
setInterval(() => this.setData(...), 10)
```

### 渲染

- 长列表分页、虚拟化或按视口加载。
- 为 `wx:for` 提供稳定 `wx:key`。
- 减少深层组件、复杂选择器、频繁布局测量和同步读写交错。
- 对高频动画优先使用适合的 CSS、WXS/Worklet 或 Skyline 能力，并做兼容测试。
- 及时释放 Canvas、视频、音频、定时器、监听器和大数组。

### 页面切换

- 跳转前避免同步重计算和大对象序列化。
- 对低频分包做合理预下载。
- 保持返回栈可控；对长流程保存恢复点。
- 不使用不可关闭弹窗或营销页拦截返回。

## 4. 网络与弱网

### 请求设计

- 设置符合业务的超时，不依赖默认 60 秒拖住用户。
- 并行无依赖请求，串行有依赖请求。
- 缓存 GET 和稳定字典；使用 ETag/版本号时正确处理失效。
- 分页和字段裁剪，避免一次返回大列表和 Base64 媒体。
- 对图片、视频和文件使用 CDN、断点/重试能力和尺寸限制。

### 重试与幂等

- 只自动重试幂等操作。
- POST/支付/创建/领取使用幂等键，服务端保证唯一。
- 指数退避、随机抖动和总次数上限。
- 用户手动重试前显示当前状态，避免重复订单。

### 弱网体验

- 超时后保留用户已输入数据。
- 给出重试、离线草稿、返回和联系开发者路径。
- 区分网络不可用、服务端错误、权限不足和业务拒绝。
- 支付后以前端 success 仅作提示，最终状态以服务端回调/查询为准。
- 上传显示进度，允许取消，失败后可续传或重选。

## 5. 测试矩阵

### 功能

- 首次用户、老用户、登录过期、已注销用户；
- 正常、空数据、边界值、重复点击、并发；
- 首页到每个类目核心页面不超过合理步骤；
- 隐藏、会员、付费功能使用审核账号完整可达；
- 返回、左滑、关闭、支付完成和取消符合预期。

### 权限与隐私

- 同意、拒绝、稍后同意、撤回；
- 新增隐私声明后的老用户；
- 低于 2.32.3 的基础库兼容；
- 后台未声明时的错误处理；
- 用户删除、退出、注销和数据清理。

### 网络与服务端

- Wi-Fi、移动网络、弱网、离线、DNS/证书失败；
- 超时、5xx、限流、重复回调、乱序；
- 越权 ID、角色伪造、价格篡改、恶意文件；
- 会话过期、token 重放和多设备登录。

对声称“无网络/仅本地”的项目增加反向验收：静态扫描构建产物中的网络/云调用/远程资源和第三方 SDK，断网真机走完核心流程，并保存开发者工具网络面板与真机证据。没有后端时将服务端专项标记为 `N/A（无后端，证据：构建扫描 + 离线测试）`，不虚构接口测试。

### 终端与基础库

- iOS、Android，按用户覆盖 HarmonyOS、Windows/Mac；
- 低端机与主流机；
- 最低、主流、最新基础库；
- 深色模式、字号放大、横竖屏/大屏、安全区域；
- 开发者工具只作一层，不替代真机。

### 内容与运营

- 文本、图片、音频违规样本和对抗变体；
- 举报、删除、封禁、申诉、巡查；
- 分享/订阅在拒绝后仍可使用核心功能；
- 广告加载失败、关闭、误触和主流程遮挡；
- 联系、投诉、侵权和售后渠道可用。

## 6. 自动化与 CI 门禁

建议流水线：

```text
依赖锁定/安装
  -> lint/typecheck/unit
  -> 小程序静态审计
  -> 构建 npm/产物
  -> 路由和包体检查
  -> 自动化核心路径
  -> 隐私 API 与清单差异
  -> 预览二维码/体验版
  -> 人工真机与审核材料确认
  -> miniprogram-ci 上传
```

### 静态审计

运行：

```bash
python3 scripts/audit_miniprogram.py /path/to/project \
  --subject ordinary-personal \
  --format markdown \
  --fail-on P1
```

扫描结果分为：

- `P0`：明显秘密泄漏、普通个人使用硬性不开放能力、路由损坏等阻断；
- `P1`：高概率审核/安全/隐私问题；
- `P2`：质量、性能或需人工确认的问题；
- `INFO`：项目清单和动态核验提示。

静态扫描无法验证：MP 后台类目/隐私声明、服务端实际鉴权、真实资质、域名备案、支付商户状态、内容安全回调、真机体验和审核结果。

### 上传

- 仅受保护分支可访问生产上传私钥。
- 版本号、描述、commit、构建时间和机器人编号可追溯。
- 默认开启代码上传 IP 白名单。
- 不在日志打印私钥路径内容、二维码敏感参数和完整环境变量。

## 7. 发布候选标准

只有满足以下条件才标记 `release-candidate`，仍不得说“保证过审”：

- [ ] 主体、类目、资质、备案和能力已实时核验。
- [ ] 构建、类型检查、测试和静态审计无 P0/P1 未解释项。
- [ ] 真机覆盖目标终端和最低基础库。
- [ ] 冷/热启动、更新、弱网、拒绝权限和会话过期已测试。
- [ ] 隐私清单、后台声明、代码和 SDK 一致。
- [ ] UGC/AI 内容治理和投诉闭环可运行。
- [ ] 审核账号、路径、备注和特殊条件完整。
- [ ] 无测试文案、空白页、失效按钮、自动播放和不可关闭弹窗。
- [ ] 线上监控、回滚/最低可用版本、旧客户端兼容已准备。
