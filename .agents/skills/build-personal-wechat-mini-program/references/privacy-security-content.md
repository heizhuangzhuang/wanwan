## 1. 隐私数据清单

在写调用代码前填写 `assets/privacy-data-inventory.csv`。每个字段记录：

- 数据/权限名称；
- 直接收集、微信提供、第三方 SDK、用户生成或系统推断；
- 具体功能目的，不能写“提升体验”等空泛表述；
- 必要性和拒绝后的降级；
- 触发页面与用户动作；
- 客户端、云函数、自建后端、对象存储和日志中的位置；
- 接收方、委托处理方、共享/转移/公开；
- 保留期、删除入口和备份清理；
- MP 后台《小程序用户隐私保护指引》声明项；
- 法律依据或用户同意；
- 敏感等级与安全措施。

对代码、后台声明和实际网络行为做三方核对。隐私政策写了但代码多收集，或代码不再收集但后台仍声明，均需整改。

## 2. 隐私协议开发

官方当前机制要点：

- 涉及个人信息的小程序需用明显方式提示用户阅读隐私规则。
- 只有在 MP 后台声明处理的用户信息，才可调用对应隐私接口/组件；未声明会被禁用。
- 每个用户需同步已阅读并同意状态，才可调用已声明的隐私能力。
- 新增隐私接口/组件后，旧用户可能需要针对新增内容重新同步。
- 基础库 2.32.3 起集成相关隐私功能；低版本需设计兼容。

### 主动模式

1. 调用 `wx.getPrivacySetting`，读取 `needAuthorization` 和协议名称。
2. 提供查看协议入口，调用 `wx.openPrivacyContract`。
3. 使用 `<button open-type="agreePrivacyAuthorization">` 让用户主动同意。
4. 在 `bindagreeprivacyauthorization` 后调用对应隐私接口。

### 被动模式

使用 `wx.onNeedPrivacyAuthorization` 监听用户触发未同步的隐私接口，并展示自定义弹窗。需要时使用 `wx.requirePrivacyAuthorize` 模拟隐私接口调用。

官方弹窗可作为兜底，但不要依赖兜底替代产品设计：

- 清楚解释用途；
- 只在功能触发时显示；
- 允许拒绝并保留无关功能；
- 避免连续骚扰；
- 对错误码 103、104、112 等做可理解处理。

不要把 `__usePrivacyCheck__` 当作关闭隐私机制的永久开关；官方已在 2023-10-17 后普遍启用相关功能。

## 3. 用户资料与敏感能力

### 登录

`wx.login` 仅提供临时 code。登录不等于取得用户头像、昵称、手机号，也不等于用户同意隐私政策。

### 头像昵称

优先使用：

- `<button open-type="chooseAvatar">`；
- `<input type="nickname">`。

微信侧从相应基础库版本开始对头像昵称做内容安全检测，但开发者仍需对存储、公开展示、举报和删除负责。

### 手机号

手机号快速验证组件目前只对已认证非个人主体开放并按成功调用计费。普通个人项目不要把手机号作为登录或核心功能的强制前置条件。

替代设计：

- OpenID 对应的匿名账号；
- 用户自愿填写联系方式并做短信验证（仍需合法短信服务和隐私合规）；
- 仅在履约确需联系时收集，并明确用途；
- 使用客服能力而非诱导添加个人微信。

### 位置、相册、相机、麦克风等

- 只在用户点击对应功能后申请。
- 说明精确用途，不用“提供服务”笼统描述。
- 精确位置、录音、相机、生物识别等按敏感个人信息高标准处理。
- 提供关闭追踪、撤回授权和手动输入等替代。
- 不在冷启动批量索权。

图片类项目按实际 API 建清单，不把不同授权层混为一谈：

| 能力 | 常见 API/组件 | 关键检查 |
|---|---|---|
| 用户选择照片/视频 | `chooseImage`、`chooseMedia`、`chooseVideo` | 用户点击后调用；后台隐私指引声明选取的媒体及用途；不因此把 `requiredPrivateInfos` 扩成通用隐私清单 |
| 拍照/摄像 | 相机来源选择、`camera` 等 | 单独说明摄像头用途；拒绝后保留相册或示例数据等无关路径 |
| 保存到相册 | `saveImageToPhotosAlbum`、`saveVideoToPhotosAlbum` | 仅在用户点击保存时触发；拒绝后保留预览/重试，不强制退出 |
| 上传图片 | `uploadFile`、云存储/第三方 SDK | 明确接收方、保留期、公开范围、EXIF 清理、内容安全和删除；不得用“选图”告知掩盖上传 |

微信隐私同步、操作系统权限和 MP 后台接口/类目开通是不同层级。每个版本从对应 API 官方页与真机行为确认，不提前批量 `authorize`，也不因缺少 `requiredPrivateInfos` 就误判相册/相机未声明。

### 剪贴板与截屏

- 只在明确用户动作后读写剪贴板；不默认读取。
- 不因用户截屏自动跳页、关闭服务或强制营销。
- 不把剪贴板当隐蔽跨应用跟踪通道。

## 4. 服务端安全

遵循“不信任前端、最小权限、默认拒绝”：

### 鉴权

- 每个敏感接口校验当前会话、角色和资源 owner。
- 防止修改 URL/ID 即访问他人数据的平行越权。
- 防止普通用户调用管理员接口的垂直越权。
- 公开信息接口也设置频控、人机校验、字段最小化和日志，避免批量爬取。

### 敏感信息

不得在小程序包、注释、配置或 Source Map 中放置：

- AppSecret、access token、session_key；
- 支付 API 私钥、证书、代码上传私钥；
- 数据库密码、云密钥、管理员密码；
- 完整身份证、银行卡、手机号和生物信息。

Base64、MD5 或 SHA1 不是安全加密。展示敏感字段时脱敏，服务端使用合适加密、密钥轮换和访问控制。

### 输入与业务逻辑

- 使用参数化查询，禁止 SQL 拼接。
- 禁止把用户输入直接拼到系统命令、文件路径和模板执行。
- 上传使用扩展名、MIME、文件头和内容多重白名单；随机文件名；与 Web 可执行目录隔离。
- 下载按资源 ID 查找并校验 owner，不接受任意路径。
- 奖励、库存、兑换、支付回调和退款使用幂等、事务或锁，防条件竞争。
- 管理后台禁用默认/弱口令，敏感操作启用二次验证。

## 5. 文件与第三方 SDK

### 文件

- 限制类型、大小、数量、频率和保存期。
- 对公开图片、音频、视频做内容安全检测。
- 清理 EXIF、地理位置等不必要元数据。
- 上传后默认私有；通过有时效、有限权限的 URL 访问。
- 防止恶意文件、压缩炸弹、路径遍历和跨用户访问。

### 第三方 SDK

为每个 SDK 记录：

- 提供商、版本、目的和官网；
- 收集字段、触发时机、网络域名和设备权限；
- 是否有独立隐私政策与委托处理协议；
- 是否在用户同意前初始化；
- 更新、漏洞、停用和数据删除方式。

不接受“SDK 文档没写所以不收集”的推断。通过代码、运行时网络和后台日志核验。

## 6. UGC 与内容安全

只要用户能提交、编辑或公开展示以下内容，就按 UGC 处理：

- 头像、昵称、签名；
- 评论、帖子、问答、聊天、弹幕；
- 图片、音频、视频、文件；
- 商品、活动、服务描述；
- AI 提示词与 AI 生成结果；
- 公开备忘、模板、二维码文案。

### 发布前

1. 对文本调用官方文本内容安全识别。
2. 对图片/音频等调用多媒体内容安全异步识别。
3. 高风险结果进入人工复核，未完成复核前不公开。
4. 对账号、频率、设备、IP、历史违规做风控。
5. 对链接、二维码、联系方式、变体词和规避字符做业务规则检查。

### 发布后

- 定期巡查与抽样复核；
- 用户举报、屏蔽、删除和申诉；
- 对违规账号限流、禁言、封禁；
- 保存必要的审核与处置证据；
- 快速响应平台投诉与监管通知。

官方明确内容安全服务并非一劳永逸。不得只调用一次接口就取消人工治理和投诉渠道。

### AI 内容

- 先区分“仅调用第三方模型 API”与“向境内公众提供生成式人工智能服务”。后者需同时评估生成式 AI、深度合成、算法备案/安全评估、内容标识、个人信息、知识产权和行业许可，不能因底层模型已备案就推断小程序运营者全部免责。
- 把提示词、上传资料和模型输出视为不可信数据；输入与输出都做内容安全，防提示注入、越权工具调用、模型窃取和敏感数据进入模型供应商。
- 明确并公开适用人群、场合、用途和局限；医疗、法律、金融、教育等高风险建议设置强限制与人工复核，不伪装真人、权威机构或确定事实。
- 记录模型/供应商、版本、输入输出安全结果、人工处置和用户申诉；只保留业务必要日志，不能因风控无限期保存完整提示词。
- 与模型供应商核对数据用途、训练使用、跨境、保留、删除、子处理者、故障和安全事件责任。

自 2025-09-01 起施行的《人工智能生成合成内容标识办法》要求在适用场景实现显式与隐式标识：

- 文本、图片、音频、视频和虚拟场景按规定在内容或交互界面提供用户可明显感知的标识；
- 下载、复制、导出时保持应有显式标识，并在文件元数据中写入生成合成属性、服务提供者/内容编号等隐式信息；
- 若提供内容传播，核验元数据、让用户声明 AIGC、对疑似生成内容添加提示，并写入传播平台相关元数据；
- 在服务协议中说明标识方法和用户义务，不得提供恶意删除、篡改、伪造、隐匿标识的工具；
- 特定情况下向用户提供无显式标识内容前，需满足协议与日志等法定条件，不能把“去水印”作为默认付费功能；
- 提审资料应如实说明是否提供生成合成服务，并准备标识实现、模型供应商、内容安全和投诉材料。

来源：[生成式人工智能服务管理暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)、[人工智能生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)。

判断角色时使用下表，结论仍需法律/监管核验：

| 场景 | 默认风险判断 | 必做动作 |
|---|---|---|
| 仅开发者内部使用，不向公众输出 | 不当然等于面向公众生成式服务 | 仍做数据、商业秘密、供应商和账号安全 |
| 小程序把第三方模型结果直接提供给境内用户 | 不能因“只是 API 调用方”排除运营者责任 | 核验自身服务提供者角色、协议、内容安全、投诉、标识、备案/评估 |
| 用户可发布、分享或下载 AI 内容 | 同时涉及生成与传播职责 | 用户声明、显式/隐式标识、导出保留、传播检测和处置 |
| 自行训练、微调或构建知识库 | 增加训练数据、版权、个人信息和数据质量风险 | 记录合法来源、授权、删除、标注和供应商边界 |
| 医疗、法律、金融、教育等高风险用途 | 行业许可与错误后果显著 | 限制功能、人工复核、风险提示；无类目/资质则阻断 |

## 7. 删除、注销与事件响应

### 用户权利

提供可发现的：

- 查看/更正资料；
- 撤回同意和关闭非必要权限；
- 退出登录；
- 账号注销；
- 删除用户数据；
- 联系开发者、投诉和申诉。

删除覆盖：主数据库、索引、对象存储、缓存、消息队列、分析副本和可控备份。法律必须保留的数据单独隔离、限制用途并告知保留依据和期限。

本地规则存在“立即删除”和“终止后 24 小时内删除”的表述差异。采用严格口径：立即停止使用，尽快执行不可恢复删除，最迟不超过明确适用规则要求；腾讯共享数据不得仅凭用户同意擅自继续留存或转交。

### 安全事件

发现泄漏、越权、密钥暴露或违规内容扩散时：

1. 立即止损：撤销密钥、关闭入口、隔离数据、阻断传播。
2. 保留日志与时间线，不销毁证据。
3. 评估数据类别、人数、范围和实际后果。
4. 按法律和平台要求通知腾讯、用户和监管部门。
5. 修复根因并验证，不只重置密码。
6. 更新权限、监控、测试和应急预案。

## 8. 审计清单

- [ ] 后台隐私声明与实际 API/SDK 完全一致。
- [ ] 权限只在用户触发对应功能后申请。
- [ ] 拒绝权限不影响无关功能。
- [ ] AppSecret/session_key/私钥不在前端或仓库。
- [ ] 服务端做身份、角色、资源级鉴权。
- [ ] 上传、下载、SQL、命令和路径参数有白名单/参数化保护。
- [ ] UGC 在公开前完成机器检测和必要人工复核。
- [ ] 有举报、屏蔽、删除、封禁、申诉和巡查。
- [ ] 第三方 SDK 有字段级审计和合同约束。
- [ ] 用户可以退出、注销、更正和删除数据。
- [ ] 日志和备份执行最小化、脱敏、权限和保留期。
- [ ] 有数据事件止损、通知、报告和复盘预案。
